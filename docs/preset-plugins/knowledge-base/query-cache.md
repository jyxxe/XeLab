# 查询自动缓存与容量上限

[知识库目录](README.md) · [链式语言](query-language.md) · [查询执行](query-execution.md) · [索引一致性](index-consistency.md)

> 规格版本：2.6.0；状态：设计契约，尚未实现。

## 三类缓存对象

| 类别 | 内容 | 淘汰后的影响 |
|---|---|---|
| data | 完整、有序、去重的ID列表、中间链前缀、必要排序状态及每个topk阶段的分数/覆盖元数据 | 查询可重新计算，不改变完整列表语义 |
| text | 按显式规则读取的纯文本、显式预处理及chunk策略结果 | 重新预处理，不修改业务行或隐式开启自动分块 |
| vector | 查询embedding向量，以及已持久字段向量的只读派生读取页 | 重新编码/读取，SQLite中的持久业务向量索引不被删除 |

data缓存不把一页ID、尚未完成的扫描或超时结果标记为完整列表。text缓存所需的文本副本和派生结果全部受本类字节上限约束，不能把整表正文作为无上限旁路缓存。三类均不保存用户令牌、可重用授权句柄或可执行表达式。

链式查询按原顺序执行，可复用已经完整计算的前缀。例如`a.match(P).topk(...).match(Q)`可复用`a.match(P)`或`a.match(P).topk(...)`，再执行剩余阶段。后置match仍只筛选当前列表，不向先前topk回补；命中缓存不允许把它前移或重新扩大候选集合。

每阶段完整ID集合最多100000项，超限明确失败；缓存压力不能成为截断集合、改变k或跳过查询阶段的理由。是否缓存不改变查询结果、顺序、快照水位和完整性说明。

## 配置

知识库插件配置对象`query_cache`由[清单Schema](manifest.json)、[默认配置](defaults.json)及[部署模板](deployment.template.json)共同定义。

| 字段 | 默认值 | 约束与行为 |
|---|---|---|
| enabled | true | false时不读取、不发布缓存并清空已有条目 |
| data_max_bytes | 128000000 | 整数0..2147483648；data类上限，0只关闭并清空本类 |
| text_max_bytes | 128000000 | 整数0..2147483648；text类上限，0只关闭并清空本类 |
| vector_max_bytes | 128000000 | 整数0..2147483648；vector类上限，0只关闭并清空本类 |
| max_entry_bytes | 8388608 | 整数1..16777216；单条完整对象上限，准入还必须满足所属类预算 |
| ttl_seconds | 300 | 整数1..86400；从成功发布时开始计时，命中不延长TTL |

各类默认128 MB，采用SI单位：128 MB=128000000字节，三类合计384000000字节；不是每类128MiB。单条默认8MiB、TTL为5分钟。删除旧max_bytes字段，不能同时接受旧总额和新分类限额。

三类上限之和必须同时≤2147483648字节且≤实例memory_bytes/2，应用配置或降低实例内存时共同校验。Schema校验各字段范围，Initialize在分配前验证总和与当前实例内存，不合法时拒绝就绪。每类预算为整个知识库实例共享，计入预设4GiB内存限额，不按账户、表、字段或并发请求复制。类间不借额；关闭text不将其128 MB赠给data或vector。

每个对象按主要payload归入一类，键、容器容量、索引、LRU结构、引用元数据和临时准入副本跟随该类保守计量，避免同一普通对象重复记账。混合payload应拆成独立可计量对象；无法拆分时按所有涉及类别分别保守计量，不能只将大向量/文本记成小型ID元数据而逃过分类限额。

执行中的查询工作区另受候选数量、阶段数量、并发、deadline和容器内存限制；缓存上限不代表全部查询峰值内存上限。增加缓存配额不自动增加插件资源或借用内核预留。

## 分类缓存键与有效性

所有类别均按可信subject_id及原来源批准集合隔离，命中时重新核实当前账户/祖先/源凭证、表owner ACL、当前Skill及原目标动作。当前权限缩小、Key条件失效、表被归档或源值变化时，旧缓存不能成为继续读取的凭证。

data键至少包含table_id、当前部署内固定rows-query契约/语言版本摘要、规范化AST与类型化参数、输入ID列表及顺序摘要、前缀边界、排序状态、require_complete_index、schema_revision和data_revision。列使用稳定field_id，不按原始字符串模糊命中。涉及topk时还包含所有相关字段的generation、index_revision、space、维度及预批准候选集合；每阶段保存本次实际选用provider元数据，选中的query候选UUID/摘要也纳入data键，主备选择变化时未命中并重算，以保持审计一致；vector类仍可同空间跨接口复用。

text键包含规范输入摘要、文本/媒体源摘要、预处理/tokenizer/chunk策略版本及适用的purpose/prefix；表内源值还需绑定table/field及schema/data水位。只有显式声明的预处理可复用，不因缓存而自动截断正文、改变分块方式或将document前缀误用为query前缀。

查询embedding的vector键绑定embedding_space_id、维度、purpose/prefix、规范输入及原来源预批准候选集合；不将本次实际主/备接口ID作为键的一部分。同空间、同预处理的获批text-1/text-8接口可复用，但缓存记录原计算来源供审计。持久字段向量读取页还需绑定table/field、generation/index_revision、行及source_hash等内容水位。

index_revision在可见向量内容或ready/pending/failed/skipped状态改变时同事务递增；generation变化也使其单调递增，不重置。即使原始行数据和generation没变，reindex继续完成一行也会使旧向量缓存失效。

文本查询优先text-1、索引构建优先text-8；fallback只允许固定预批准、当前获权且可用、输入模态/额度适配并且维度/空间一致的候选，不能因命中或回退越权或换向量空间。候选选择详见[字段向量配置](vector-indexes.md)。

vector命中及data中的topk命中，仍需在原来源预批准集合中至少存在一个当前获权、ready且能处理该输入的同空间provider。经[HostService.CheckSkillAccess](../../rpc/HostService.CheckSkillAccess.md)核实适用的固定Skill及摘要，返回前再次检查当前委托；主接口不可用可检查合规备用接口，不要求旧计算接口仍可用，也不能因为旧向量存在而绕过全部provider不可用的限制。

CheckSkillAccess不运行模型、不创建业务Call或扣推理额度，也不提供可复用授权票据；只有skill.read的ResolveSkill不足以证明可以调用。实际未命中调用仍由InvokeSkill校验输入和Blob等资源。不同subject不共享条目，同主体不同Key仍按各自当前权限验证。

require_complete_index=false的合法部分索引结果可缓存，但键与完整模式隔离，并保留每个topk阶段的完整覆盖计数；不能供true请求复用。TTL只控制条目寿命，不能代替水位和权限校验。

## 准入、淘汰与并发

仅在阶段完整成功、结果及必要元数据全部就绪后原子发布；超时、取消、授权失败、未完成扫描或超硬上限结果禁止发布。查询快照在填充期间已过期时，不能将旧结果标为当前水位的缓存；可直接丢弃该次填充，按正常快照语义返回查询结果。

每类独立清理过期/水位失效项并按本类LRU淘汰，直至对象及临时准入副本同时满足max_entry_bytes和本类预算；不跨类腾借预算。命中只更新本类LRU，固定创建TTL不变。单条超限、所属类预算不足或分配失败时作为未命中/放弃填充处理，正常执行仍服从原查询硬限制，不返回缩短的ID列表。

并发相同缓存键的填充可合并，但不共享用户授权上下文；等待者保留各自deadline和取消状态，发布前仍校验自身授权。任何读引用尚未释放的条目继续计入驻留量，不能从LRU移除后就假定内存已释放。

降低任一类上限/max_entry_bytes或关闭缓存时，先暂停相关类别新准入，淘汰到新上限或清空，再确认运行配置应用成功。现有平台通过recreate停止旧进程、清空缓存后以新限额启动；updateDeployment写入期望配置不等于新实例已Ready。类上限0只影响本类，enabled=false清空三类。生命周期操作未成功时不得报告新运行代次Ready，不能先确认新上限再让旧缓存长期超额；提高限额仍需满足总和及实例内存约束。

## 生命周期与可观测性

三类缓存仅存插件进程内存，不写SQLite，不包含在业务备份中；插件重启、升级或恢复后从空缓存开始。vector缓存的读取页不是业务向量索引，缓存清空/淘汰不会删除持久表行、文本、向量或已返回的ID列表，也不承诺持久结果句柄。

缓存故障只作为未命中，不降级授权、完整性检查或硬限制。指标按data/text/vector分别记录命中、未命中、过期、水位失效、容量淘汰、拒绝准入及当前计量字节；指标/日志不保存原文、参数、完整ID列表或用户凭证。

全表根a的缓存输入身份用table_id及schema/data水位标记，无需为查缓存先扫描整个根列表；显式input_ids则哈希完整顺序。命中前仍验证全部参数，尤其同表media_id存在/模态/摘要，媒体GC不一定推进data_revision，不能仅凭旧参数摘要跳过这一检查。模型内部tokenization由embedding插件管理，KB缓存不改变已有embedding请求协议。

cache.state/hit_stages/stored_stages仅描述data列表/前缀复用；cache.classes分别给出data/text/vector在本请求的hits/stores，不公开其他账户全局使用量。
