# iframe应用窗口管理

[WebUI目录](README.md) · [插件隔离](../../plugins/ui-contributions.md)

> 规格版本：2.8.0；状态：待实现的规范。

窗口外壳由WebUI绘制，iframe只占内容区。标题、插件来源、固定版本提示、关闭/最小化/最大化和加载错误由宿主控制，插件不能伪造宿主窗口权限或改写外部标题栏HTML。

每个窗口拥有浏览器内随机view_id、贡献键(deployment_id,contribution_id)、安装/贡献摘要、逻辑像素矩形、状态和焦点序号。同一贡献允许多窗口，各自消息通道/请求去重独立；最多16个打开窗口，最小化窗口也计数。

| 状态/操作 | 行为 |
|---|---|
| loading → active | 核对当前贡献，创建跨源iframe，10s内完成握手后可调用桥 |
| focus | 点击标题/内容或窗口列表激活；壳重新分配有界z-index，不信任插件传入层级 |
| drag/resize | 标题栏拖动，边缘缩放，遵守UiWindowSize；控制区始终可达 |
| minimize | 隐藏到Dock，发送visibility=false，暂停页面刷新；显示已有任务标记 |
| maximize/restore | 保存原矩形后铺满工作区，再恢复并夹回当前视口；不抢占浏览器全屏 |
| close | 移除iframe、销毁桥nonce/待处理UI回调；不取消已提交batch |
| failed/disconnected | 宿主展示错误、重试和贡献版本；不能无限重载或透明替换模型 |

第一版最小化保留iframe但暂停宿主发起的刷新；页面仍可能消耗浏览器CPU，属于不可信进程，壳可在压力下卸载。卸载后重新握手，不恢复未确认的同步副作用调用，不假称postMessage可以冻结任意JavaScript。

关闭时可提示尚未保存的本地编辑，但插件消息不能永久阻止关闭；任务中心保留已获得batch_id。窗口内部调用超时/网络断开按稳定幂等键核实，不把窗口关闭当成已回滚写入。

恢复仅保留当前浏览器、当前用户的贡献键和窗口矩形，不能存业务输入、令牌或结果。原部署/安装/贡献摘要变化时展示待重新加载状态，重新取当前白名单；不把旧iframe的新增权限悄悄放行。
