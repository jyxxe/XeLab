# WebUI异步批次与任务中心

[WebUI目录](README.md) · [核心batch协议](../../skills/batches.md)

> 规格版本：2.8.0；状态：待实现的规范。

批量embedding、行导入/删除、多个表达式查询和有界索引更新默认提交异步batch。表单展示项目数、每项粒度、目标固定Skill、并行度、失败策略及执行身份；默认max_parallel=1，failure_policy=continue。

提交前为本次意图生成稳定Idempotency-Key，校验所有输入并禁用重复提交按钮。收到202即展示batch_id并加入任务中心，不等同“已完成”；断网且未获响应时以原键重试提交，不能换键再开一批。

任务中心按batch_id去重，统一为多个窗口/组件复用轮询；1s起步退避到30s，页面隐藏降低刷新频率，恢复后立即查询一次。关闭窗口、卸载组件或重启浏览器不会取消核心已接受任务；重新登录后从listSkillBatches恢复，不依赖内存Promise。

列表显示状态、成功/失败/取消/未知/总数、固定目标、创建/截止时间；详情按index和item.id定位，失败展示稳定错误与当前可操作原因。进度以已确认完成数为准，unknown单列且不能显示100%成功。

结果逐项分页按需领取，已成功项可提前查看；大向量/媒体不全部塞进桌面内存。HTTP200的批次查询、合法的reindex统计、以及某些行已写入都不能替代“整批全部成功”判断。

取消先读取当前ETag再请求核心；遇412重新显示最新状态。cancel_requested仍显示收敛中，已提交数据保留，unknown需核实。移除UI组件不等同取消业务。

paused_authorization展示来源到期/撤权原因，同一owner显式重新授权后调用resume；不自动转用WebUI服务凭证。跨会话长期执行需要事先批准服务账户，不能捕获旧浏览器token作为后台任务身份。

“重试失败项”构造新批次并明确只选已确认failed/canceled且可安全重做项；unknown不自动重试，非幂等写入需先核实。新的批次不是原事务回滚后的重跑，已成功项不重新提交。

有单独batch.resolve权限时任务中心可提交未知结果的人工核实与证据，必须标明manual来源，确认未执行也不会自动重放；普通Member模板不默认获得这项核实权。

索引全量维护以多个有界reindex单元和vector-status驱动，不无限延长一个Skill请求；需要直到无pending的持久编排时用已批准核心工作流/定时计划逐轮提交，下一轮读取实际游标/代次，不预填尚未知的续点或空转轮询。

知识库每个查询item返回完整ID列表；批次items分页只是任务状态分页，不得分页截断单个表达式ids。行正文通过rows-get另行读取，缓存命中不省略当前授权和index_revision检查。
