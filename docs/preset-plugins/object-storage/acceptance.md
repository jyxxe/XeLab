# 对象存储待实现验收

[对象存储目录](README.md) · [接口](interfaces.md) · [存储一致性](storage.md)

> 规格版本：2.6.0；状态：设计验收要求，尚无实现或压测结果。

## 内容与接口

1. 零字节与恰好67108864字节文件可经Blob导入并完整导出；大于64MiB明确拒绝，不通过base64、分段JSON或临时文件绕过。
2. 实际流长度、offset或SHA-256与声明不符时不发布对象；超长流及时停止，不用无界内存缓存校验。
3. 所有六个Skill的输入拒绝未知字段，输出符合对应Schema；不接受owner_id、宿主路径、任意URL或S3签名地址。
4. NFC和1024字节边界按UTF-8验证；非NFC、控制字符、反斜线、绝对路径、空段、`.`/`..`段拒绝；URL编码文本不经解码变成路径。
5. 任意文件类型可作为不执行的字节存储；content_type格式校验，CR/LF拒绝，不能因MIME声明触发脚本执行、外网读取或无界解码。

## 并发与恢复

6. create同key并发只有一个成功；同revision的replace/delete竞态至多一个提交；覆盖保持object_id/created_at、递增revision。
7. 首次create为rev1；replace为rev2，delete消耗rev3，重建同key为新ID/rev4。永久head/tombstone经GC/重启/备份恢复不回退；旧delete/export的expected_revision=2不能误匹配重建对象。
8. 相同业务键和指纹在重启后返回原结果；同键不同指纹冲突。先重放再CAS，不能因首次操作改变revision让安全重试失败。
9. 在预留、复制、fsync、rename、数据库提交和应答前后注入崩溃；不出现可见半文件，恢复计数正确，未引用文件有界GC，已提交结果可核实。
10. export在Host.WriteBlob发布和本地结果保存之间中断时，通过核心输出账本与结果查询核实；无法核实标记unknown，不盲目创建第二份。
11. 源Blob过期不影响持久对象；导出Blob过期后同键仍引用原结果，新键才创建新Blob。源对象删除不能被宣称撤回已下载副本。

## 容量与分页

12. 用户logical_bytes+reserved_bytes及对象数预留原子准入；并发创建、覆盖、取消、失败、重启不会超卖或泄漏额度。
13. 覆盖新旧内容同时占盘、删除后等待GC、未发布文件和导出读取pin均计入相应实际部署预算；不能仅用逻辑净增代替物理占用。
14. 默认用户1GiB/10000对象、部署16GiB及20GiB卷硬配额共同生效；永久head/tombstone等元数据计入部署/卷预算，WAL/索引等计入实际卷，文件系统写满明确失败，不返回虚假持久化成功。
15. 创建子账户或多个API Key不扩大部署预算；不同用户不能借usage响应获知其他用户占用。低于已占用/预留的配置变更拒绝且不自动删文件。
16. list按UTF-8字节序、prefix与1..200条界限返回；`prefix="reports/"`合法，空prefix匹配本用户全部key。空结果的next_cursor为null。
17. 同一向前遍历不重复越过的key；并发增删改按逐页当前视图处理，不承诺全库快照。游标subject/条件/代次不匹配或15分钟过期时明确冲突，不能变成新首页。

## 权限与运维

18. 父子账户、同角色用户、Guest和Operator均不能仅凭关系跨用户读写；伪造owner/header/游标不改变可信subject，API Key仍受自己的固定上限。
19. 源Blob无权时put拒绝，导出需当前获准Blob创建与读取；旧结果、旧委托及成功游标不能恢复已撤销的权限。
20. single_writer卷不能双实例并发写；禁用、升级、卸载不删除业务卷。备份/恢复同时覆盖SQLite WAL和内容清单，损坏摘要不Ready或不导出成功。
21. 六个Skill通过核心固定版本路由；批量操作使用异步batch逐项查询，允许部分成功，无跨项隐含事务；取消和重试不绕过CAS/幂等。
22. 活动4、队列32、排队5000ms和原总deadline同时有效，1GiB内存/256MiB临时盘内持续传输可控。上述数值须实际资源验收，文档校验不能替代真实I/O、崩溃恢复或隔离测试。
