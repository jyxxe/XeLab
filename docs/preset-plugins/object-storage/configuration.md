# 对象存储配置与预算

[对象存储目录](README.md) · [存储协议](storage.md) · [节点预算](../../runtime/budgets.md)

> 规格版本：2.8.0；状态：待实现的配置契约。

配置由核心部署管理接口保存，通过Initialize应用；文件读写权限不赋予部署配置权。配置变更按现有部署重建与新代次流程生效，不假设存在未定义的热重载接口。

## 实例与卷

| 项目 | 初始建议 | 约束 |
|---|---|---|
| CPU | 1000mCPU | 从插件资源池扣除 |
| 内存 | 1073741824字节，1GiB | 包含SQLite缓存、索引、所有传输缓冲和管理进程 |
| 临时盘 | 268435456字节，256MiB | 不作为无限制上传中转区 |
| pids | 128 | 受普通OCI实例隔离约束 |
| 持久卷 | 21474836480字节，20GiB | single_writer，独占挂载`/data/objects` |
| 活动/排队 | 4/32 | 实例合计，不按用户复制 |
| 排队期限 | 5000ms | 仍计入原调用总deadline |

复制文件时采用不超过256KiB的有界流缓冲，不把整个64MiB文件常驻内存。实例资源不足时不能通过无界队列、缓冲或后台任务绕过准入。

## 配置字段

机器定义见[manifest.json](manifest.json)和[defaults.json](defaults.json)；下表给出本预设默认值与语义。

| 字段 | 默认值 | 定义 |
|---|---|---|
| `engine` | `sqlite` | 私有元数据后端，启用WAL；不使用核心账户数据库存文件 |
| `data_path` | `/data/objects` | 已批准卷内固定路径，不接受用户宿主路径 |
| `maximum_object_bytes` | `67108864` | 单对象最多64MiB，零字节对象合法；不能大于核心Blob上限 |
| `maximum_active_requests` | `4` | 全实例业务上限，不能放宽manifest准入 |
| `default_user_quota_bytes` | `1073741824` | 单个subject的可见对象内容及上传预留共同使用的逻辑字节上限 |
| `default_user_max_objects` | `10000` | 单个subject的可见对象数与待创建对象预留上限 |
| `deployment_storage_budget_bytes` | `17179869184` | 16GiB部署数据预算，覆盖保留内容、head/tombstone等私有元数据、未发布上传及等待GC的旧内容 |
| `idempotency_ttl_seconds` | `86400` | 已完成业务幂等/结果记录保留24h |
| `list_cursor_ttl_seconds` | `900` | 分页游标固定有效期15分钟，读取不续期 |

Initialize必须核对配置、manifest并发、实际实例资源与卷容量。不得以默认值代替实际挂载结果，也不能仅凭目录存在就报告容量配额可用。

## 三层容量

用户层限制自己的logical_bytes、reserved_bytes和对象数；部署层限制共享卷上全部保留内容及预留；卷层由核心管理的文件系统硬配额限制实际占用。三者同时满足才接受写入。

覆盖写入仍需先存一份新的不可变内容；新文件、旧文件和GC滞后可能同时占盘。部署层按实际保留内容及预留计量，不能只以新旧逻辑差值判断物理空间是否足够。用户层的覆盖预留可以按`max(新长度-旧长度,0)`计算，但必须锁定对应旧revision，不能让同一旧值被并发覆盖重复抵扣。

用户逻辑量不包括其他用户内容，也不把WAL或幂等索引伪装成某用户文件。永久head/tombstone、幂等索引等元数据仍受部署和卷物理预算限制；部署16GiB与卷20GiB之间的余量用于WAL增长及运行余量，不保证永不写满，文件系统返回满额仍须中止未提交写入。

本版的每用户配额按当前subject计算，不声称实现账户树累计存储配额。增加子账户不会扩大部署预算或物理卷，但也不会自动让父账户获得子账户文件访问权。

降低部署总预算到当前已占用或已预留以下时拒绝配置变更，不静默删除对象。禁止通过禁用、重启、GC进度延迟或创建更多Key重置占用计数。

每用户默认额度在首次创建命名空间时复制到os_users持久记录；修改default_user_quota_bytes/default_user_max_objects只影响新命名空间，不偷偷重置现有用量。本版未提供输入owner_id改他人额度的业务接口；实例/卷总预算始终同时约束全部用户。
