# MPR部署、故障与恢复

[MPR目录](README.md) · [配置](configuration.md) · [核心部署](../../operations/deployment.md)

> 规格版本：2.6.0；状态：待实现。资源建议尚未通过并发、内存峰值或故障恢复验收。

## 一份Runtime，多份微插件

MPR以`org.xelab.micro-plugin-runtime@1.1.0`普通OCI插件安装和部署。默认单副本、无持久卷，data_schema_version=none；镜像、引擎构建和安装摘要仍受平台制品审核与生命周期约束。

建议1000mCPU/1GiB内存/256MiB临时盘/pids128，活动4、队列32/5s，均从插件池扣除。宿主基础设施另行预留，不能为运行更多微插件降低内核至少4C16G预留。

微版本及代码由核心持久保存，微部署绑定明确Runtime安装/部署。微插件不需要镜像构建、独立容器、宿主端口或数据卷；它使用的是Runtime内部有限执行单元，不是另一个平台容器。

## 启动与就绪

MPR先验证受限JS引擎、虚拟I/O、heap/stack限制、可强制终止单元及父资源限制，再报告Ready。缺少可靠中断/强杀边界时，不能通过退化到普通Node/Python子进程继续就绪。

核心只在当前Runtime安装/部署已批准且实例Ready后为绑定微部署准备制品。Prepare发生在有界资源下；缓存缺失时准备原固定摘要，不自动从名称、最新版本或外部URL取替代代码。

MPR就绪不是所有微插件自动启用，也不自动批准代码。发布微版本不生成候选；新建MicroDeployment才生成candidate_skill，初始disabled且不自动register/enable。具体微部署、注册后的Skill和来源链均须当前有效；核心本身和其他OCI插件不等待MPR才能启动。

## 排空与关闭

停用先撤销新微调用路由，拒绝新排队/执行，按当前deadline处理在途请求；Drain只等待有限时间。到期后取消对应执行单元，Shutdown结束worker并释放缓存，不无限等待用户脚本主动退出。

单个worker崩溃只影响其调用，监督器需释放槽并记录失败。MPR整体退出可能影响该实例承载的全部微调用；核心将相关微部署标记waiting_runtime并核实Call，不把同实例共享视作每微插件独立故障域。

## 重启、升级与缓存

Runtime重启、升级或恢复后缓存为空。核心从自己的不可变微制品记录重新准备，不能依赖旧进程内存或临时盘恢复代码身份。LRU淘汰只释放缓存，不归档微版本或撤销核心已保存结果。

更换Runtime安装需显式发布固定新安装的微版本，再创建新MicroDeployment和Skill；修改父Runtime部署或limits也须新建微部署，现有绑定不可原地替换。waiting_runtime不授权自动换到另一个安装。旧实例/代次的迟到消息不能覆盖新执行结果。

核心保存Call状态与成功结果；无持久卷的MPR不承诺跨重启恢复自己的执行内存。未确认结果依side_effect=none及固定版本安全恢复规则处理，不能误报脚本已完成或悄悄改用新版代码。

## 容量管理

制品缓存默认256MiB、最多128份、TTL300s。受控worker地址空间默认上限128MiB，活动worker最多4，sandbox工作区总预算512MiB、控制端预留128MiB；全部worker、VM、缓冲和缓存共享1GiB父内存预算。Initialize验证缓存+工作区+控制预算不超过父memory_bytes，默认合计896MiB。地址空间不是RSS，不能据此宣称每worker拥有独立cgroup。

单微部署默认1并发、硬4，同一MPR实例合计最多4；增加微插件或微部署数量不会复制出新资源池，也不创造按MicroPlugin跨父实例的隐含全局并发计数。超出活动/排队限制时明确拒绝或等待，不启动无限worker。

默认wall2s、heap16MiB并不证明4个最坏输入可同时稳定运行。发布前需以最大输入、最大输出、编译开销、日志洪泛、取消和引擎异常测量峰值，按结果调整建议资源与验收范围。
