# M2 新卷恢复、预留与受控切换

[实施与验收](README.md) · [备份任务](m2-backup-jobs.md) · [持久卷](m2-volumes.md)

本增量接入 `restoreBackup`。来源必须是已验证的宿主外备份，目标必须属于当前主体，安装镜像和清单摘要须与备份精确一致，当前仅支持 `data_schema_version=none`。Schema 改变、全平台离线元库恢复、DataMigration 升级/回滚及正式异机灾难恢复验收仍待完成。

## 请求与准入

请求必须明确 `allow_downtime=true`。除 `backup.restore`、目标 `plugin.read`/`plugin.enable` 外，还需创建自己新卷的 `volume.create`、来源卷的 `volume.read` 和当前目标卷的读取权限。目标全部卷需属于该主体，不能有部署外附件；来源及目标的卷组必须匹配已签名的安装声明。不会接受任意文件路径、URL、对象键或镜像。

预先核对受管后端、主密钥引用、来源清单与安装摘要，然后计算新卷 XFS 几何。API 事务在停止目标写者之前持久预留所有新卷字节、inode 元数据预算、唯一 UUID 和永不回收的 project ID，同时保存恢复任务、原始权限来源、旧卷占用和新旧映射。预算不足时不提交停用目标的意图。来源卷和旧目标卷均不被覆盖。

内部迁移目标为 **8**，追加私有恢复分配状态及映射约束，保留原基线与 v1～v7 校验和。停机后执行 `xelabctl migrate --config /etc/xelab/kernel.toml --target 8` 再启动。旧二进制拒绝 v8，不能直接回退。

## 恢复与中断

后台监督任务持有部署运行时锁，重新验证原始凭证、Grant 来源、占用、当前安装及来源备份状态，再完整下载和认证清单。目标若仍运行，会先尝试排空，再以 Runtime.stop 证明旧 task、container、挂载和整个 cgroup 退出；恢复的一致性来自已验证的备份，不把强制停止旧目标当成旧数据的一致性备份。

数据只写未发布的新 UUID/project 目录。解密和归档最终记录必须完整，长度及摘要必须一致，随后再以认证归档重新核对实际落盘的文件内容、稀疏区间、链接、属性和额外目录项，并同步文件系统。网络和文件工作不持有授权事务锁。

已经持久记录为完整的新卷，在进程重启后会重新比对实际数据。`restoring` 状态不能证明提取完整，重启后会使该恢复失败并隔离私有分配，等待实际 I/O 退出后由卷 worker 清理；重试须使用新的恢复意图和 project ID。不会把非空残留目录当成空目标重新覆盖，也不会修改原卷。最终 COMMIT 结果不明时先等待任务记录锁并检查是否已经成功，避免清理一个已发布的新卷。

守护进程的宿主租约保留至进程退出，覆盖 Tokio 等待文件工作线程退出的关机阶段；下一内核不能在旧线程仍存活时接管同一宿主。

## 发布与启用

只有全部新卷验证完成，才以同一短事务发布卷元数据、更新部署卷 ID、完成操作并释放旧卷占用。发布前的文件系统检查在事务之外完成，事务内再次核对精确的预留、命名空间和配额。新卷使用新 UUID、project ID 和非零初始 fence；原卷仍保留，可单独检查和按显式卷删除协议处理。

若目标原来启用，当前权限及批准仍允许时，会为新卷安排新的实例代次。结果的 `deployment_enable_scheduled` 表示已提交启用意图，实际就绪仍由正常的初始化、健康与准入流程决定。无法安排启用时保留禁用状态。任何失败均保留原卷，清理只针对该意图独占且尚未发布的私有分配。

## 验证边界

本地已通过公开 API 对显式停机与来源 ready 状态的拒绝验证；传输层验证包括非空目标、AEAD 最终认证失败、数据和稀疏空洞损坏、取消后工作占用及已完成上传的结果恢复。真实 XFS 新卷预算/配额、私有提取/校验、发布与新 fence 已加入隔离宿主 CI，当前仍以最终提交的实际结果为准。

组件使用 MinIO 时始终 `off_host=false`，不把同机组件恢复当成生产备份 ready 或异机验收通过。真实 AWS 全链路及独立宿主恢复演练尚无通过证据。
