# M2 迁移 RPC 传输组件

[实现索引](README.md) · [升级契约](../plugins/upgrades.md)

本组件编译既有 DataMigration Proto，提供内核到插件的 Plan、Apply、Verify 客户端。
升级入口及同格式卷克隆见[部署重建实现](m2-deployment-upgrades.md)。本组件不开放
非 `none` 格式，不创建格式迁移任务，不能作为完整有状态迁移或 RUN-06 验收依据。

## 对端和请求绑定

生产连接要求宿主管理员身份。调用方必须是持有部署/卷围栏、当前完整授权、实际
插件池资源预留和已验证备份的持久升级监督任务；本传输组件不代替这些检查。
操作 UUID、部署、主体、实例/代次、源/目标 Schema 和整体期限来自持久任务。

客户端使用内核 mTLS 身份，核对目标实例与代次对应的 DNS 证书名。连接后先调用
Describe，核对返回原始字节的摘要、登记签名清单摘要及解析内容。迁移连接不会
调用 Initialize，也不因此批准写入业务数据。

每次 RPC 使用新的 request_id、原主体及稳定的 operation:phase 幂等键。
期限同时受整体任务、单调时钟和方法上限约束：Plan 10 秒、Apply 1 小时、
Verify 60 秒。普通生命周期通道仍为 30 秒；迁移专用通道允许更长的有界期限。
响应解码大小有固定上限，不把插件返回的错误文本输出为内核诊断。

## 计划与不确定结果

Plan 只接受非空规范 UUID、标准小写 SHA-256 摘要及不超过 2^53-1 的临时字节数。
返回的独占写、向后读兼容和可逆性信息供监督任务持久化并进行容量/策略准入；
这些声明本身不证明磁盘兼容。Plan 的业务数据只读挂载仍须由运行时任务实现。

Apply 要求原计划 ID/摘要、非空备份 UUID 和有效卷 fence。监督任务必须先持久化
applying 检查点；一旦交给传输，超时、断连、RPC 拒绝或响应不符合契约均返回
OUTCOME_UNKNOWN。客户端不自动重发。恢复任务应先 Verify，再决定隔离、回退或
其他已批准处理，不能将没有收到成功当成没有执行写入。

Apply/Verify 只有在 plan_id 精确匹配、succeeded=true、error 缺失且 observed_schema
等于目标时返回成功。成功响应还需由监督任务结合实际配额/数据/健康验证才能切换绑定。

## 验证与边界

`migration_rpc::tests` 使用实际 loopback mTLS、原 Proto 生成的服务和磁盘格式文件：

- 同 CA 的非内核证书拒绝，目标 DNS 名错误拒绝；Describe 字节与签名摘要不符拒绝。
- 错误计划摘要、空计划 ID、越界容量拒绝；空备份/无效 fence 不发送 Apply。
- 对端写入格式文件后故意返回 UNAVAILABLE，客户端报告结果未知且 Apply 计数保持 1；
  后续 Verify 读取文件确认格式，未重发 Apply。
- 错误计划 ID、成功携带 error、错误目标格式及磁盘格式不符均不通过；到期不再发送。

这是协议层组件验证，不是实际 OCI 迁移、只读挂载、授权围栏、可用备份或升级切流证据。
RPC 传输组件本身不创建 SQL 状态或公开接口。当前开发分支另有
[初始化监督器](m2-schema-bootstrap.md)及追加的
[Schema 13 备份登记组件](m2-format-backups.md)，非 `none` 安装入口仍关闭；
这些新增代码尚不能作为完整格式迁移的验收证明。

## 业务格式参考服务

Python 参考服务另外提供真实文件格式 1（有序记录数组）到格式 2（含顺序和长度的
记录映射）的转换；初始化只建立空格式或检查已有同格式，拒绝隐式转换。
独立的 migrating-store 插件/能力使用幂等写入契约，避免改变原无状态 echo 的摘要。
`--data-schema 1|2` 和显式的写后故障参数仅生成参考制品，内核仍拒绝非 none 安装配置。

Plan 只读业务文件，将有大小上限的计划写到独立 `/xelab-migration` 暂存项目。
计划 ID 绑定计划内容摘要，且计划绑定部署和 operation:phase；不能靠修改暂存计划
绕过 Verify。Apply 先同步绑定计划摘要/备份 UUID/fence 的记录，再原子替换并同步
业务文件；已有 applying 记录只能读取磁盘验证，不能重新执行写入。Verify 检查
实际格式、每条记录、顺序/长度及原计划目标摘要，不能只返回常量成功。

参考格式最多 64 条记录、每条文本 1024 字符，文件上限 1 MiB；临时容量声明为
3 MiB。内核仍须独立预留临时硬配额、验证可用备份、切换只读/可写挂载并持久化
自己的操作状态。这些边界不由参考服务替代；其非空备份 UUID 校验不是备份可用证明。

本地 8 项用例使用真实文件、原始 Proto、临时 CA 和实际 loopback mTLS。包含同 CA
非内核证书拒绝、只读权限下规划、初始化拒绝改格式、真实提交后 RPC 返回结果未知、
服务重建后 Verify、写后直接退出子进程、仅保存 applying 而未提交时拒绝重写、
计划/目标数据篡改及错误操作/fence 拒绝。CI 另列独立步骤重复这些检查。
权限位只读测试不是 OCI 只读挂载证据；这些用例也不证明内核迁移协调器、XFS 临时
配额、可用异机备份或公开格式迁移入口已经接通。

## 格式备份读取组件

`storage::migration_backup::Point` 实际读取有界加密清单，验证 AEAD、原登记摘要、
部署/安装/格式/主密钥引用、唯一卷别名与对象身份、容量和传输准备摘要。
它不把备份里的格式标签当成磁盘格式证明，调用方仍须取得原授权、可用备份登记、
部署和卷围栏，并通过插件 Verify 确认业务格式。

迁移前的 `verify_clone` 将实际备份数据与冻结的私有候选目录比较，拒绝未覆盖较新
写入的旧备份。归档验证可能恢复访问时间，因此只能传入私有候选目录，不能传入
仍保留的公开原卷。恢复式回退的 `restore` 仅写入新预留的空目录并独立复核，
已有或结果不确定的提取目录不能被当成新的空重试目标。原备份卷 UUID 是归档身份，
不要求等于新目标分配的 UUID。

生产格式任务必须要求实际后端的 `off_host` 证明；组件不接受调用者提供的真值。
本地兼容 S3 用例保持 false，并确认生产门禁拒绝它。用例包含实际加密对象、
新目录恢复、旧备份与候选不一致、错误安装/格式/部署/容量/对象绑定、错误密钥、
损坏对象及非空目标拒绝。数据目录和检查点以外的协调器尚待接通；这些结果不是
公开 Ready 备份、XFS、签名 OCI、业务格式 Verify 或独立宿主/AWS 的验收证明。
