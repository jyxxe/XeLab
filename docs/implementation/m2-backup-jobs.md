# M2 持久备份任务与恢复校验

[实施与验收](README.md) · [传输底层](m2-backup-transfer.md) · [备份恢复规范](../operations/backup.md)

本增量接通 `createBackup`、`getBackup`、`listBackups` 和后台一致性备份任务。新卷恢复与 `restoreBackup` 见[恢复实现](m2-restores.md)；全平台离线备份恢复、数据 Schema 迁移和正式 BACKUP-01/RUN-03 验收仍待完成。工作区组件通过不能表述为完整 M2 或真实 AWS 异机恢复验收通过。

## 宿主配置与升级

使用现有 `storage.off_host_backup_uri` 指定已存在的 AWS S3 bucket 和节点专用前缀，设置宿主环境变量 `AWS_REGION` 与 `XELAB_BACKUP_CREDENTIALS_FILE`。凭证 JSON 文件须满足现有私有文件校验，包含 `access_key_id`、`secret_access_key`，可选 `session_token`。不通过公开 API 传入端点、路径或凭证；兼容服务的 loopback 测试端点不进入生产配置。

连接需要读取与条件写入受管对象、分片写入/完成/中止及列举该 bucket 的分片上传。服务不会创建生产 bucket。主密钥继续从既有 `security.master_key_file` 加载，只保存指纹引用，恢复需要单独保管的相应主密钥。

内部迁移目标为 **7**，追加仓库注册、任务、部署占用和逐卷传输日志；原 SQL 基线及 v1～v6 校验和保持。停机后执行 `xelabctl migrate --config /etc/xelab/kernel.toml --target 7` 再启动本版本，旧二进制拒绝 v7。

## 请求、权限与冻结

备份要求同一主体拥有部署及全部来源卷，具备 `backup.create`、目标部署的 `plugin.read`/`plugin.enable` 和来源卷的 `volume.read`。必须选择部署的完整卷组，部署须处于启用、ready 的当前实例代次。当前每卷容量最多 63 GiB、明文归档最多 64 GiB；最多两个部署同时被恢复任务占用，单任务期限一小时。

API 原子保存操作、`creating` 备份、原始凭证/来源路径、安装摘要、卷快照、部署与卷占用，并停止新调用。后台监督任务独立于 HTTP 等待者，保留部署运行时锁至文件工作实际退出。控制器获得同一锁后才检查持久占用，防止旧一轮调谐在停止证明之后重新创建写者。进程内锁即使数据库连接丢失也保留；数据库会话锁和现有宿主租约继续提供其他边界。

只有插件明确返回不再接受请求、活动调用为零且排空完成，随后 Runtime.stop 证明旧任务、容器和整个 cgroup 消失，才同步文件系统并记录一致性点。强制终止成功不能替代排空成功。复制和网络 I/O 不持有授权事务锁；准备完成与最终提交再次验证原凭证、原 Grant 来源、部署身份及全部占用。新取得的 Grant 不能补活已撤销来源。

## 日志、读回与恢复边界

仓库 UUID 先登记入元库，再条件发布远端身份标记。另一数据库不能采用同一前缀；就绪仓库丢失或更换标记会拒绝继续。对象位于该仓库 UUID 的子前缀。

分片身份先落库再开始传输，所有归档/加密工作成功后，在分片完成之前保存精确摘要与 ETag。进程中断后，已准备任务只接受完整 GET、密文摘要和 AEAD 验证；响应丢失不能变成盲目重写。重新进入提交阶段也会核验所有对象。失败分片按精确对象键有界列举和中止，前缀相邻对象不被处理；失败记录继续参加对账，以捕获迟到的初始化结果，不删除可能已发布的数据对象。

清单包含部署配置、安装/镜像摘要、卷规格与数据 Schema 引用、逐对象验证摘要、创建者、时间、密钥引用及部署元数据快照的 WAL 位置。它是部署级数据和元数据快照，不能替代全平台 `pg_dump`、Blob/制品及独立密钥的恢复方案。清单先持久化，再加密发布并完整读回。只有标准远端后端和全部验证成立，才提交 `ready/off_host=true`。

成功后按原权限和当前批准尝试重建源部署的新实例代次；无法恢复批准时保留禁用状态。结果的 `deployment_enable_scheduled` 表示已提交启用意图，实际就绪仍由初始化、健康与准入流程决定。失败保留原卷，在证明旧写者停止后释放占用，部署保持禁用。最终 COMMIT 结果不明确时先锁定任务记录等待结果，已成功的任务不会被失败清理再次停止。

传输底层恢复只写新私有目录，并在解密、归档最终记录和摘要通过后，第二次以认证归档逐项对照实际落盘内容、空洞、属性、链接与目录。稀疏空洞只扫描实际 extent，不展开逻辑空洞；异常非零内容、额外条目和异常硬链接均不能通过。访问时间在校验后恢复。新卷配额分配和部署切换事务见[恢复实现](m2-restores.md)。

## 验证记录

已本地通过真实 PostgreSQL/MinIO 的仓库隔离与中断恢复、加密清单不覆盖、分片准备日志先于完成、撤权阻止发布、HTTP 备份读取与占用验证。兼容测试服务始终 `off_host=false`，数据库夹具保持 `creating`，不作为生产 ready 或 OCI/XFS 端到端证明。

存储回归覆盖已完成上传的响应丢失恢复、错误持久摘要、日志拒绝、中止、精确分片范围，以及恢复后实际字节和稀疏空洞损坏检测。数据库连接终止测试确认本进程其他运行时任务仍不能取得原部署锁。真实 AWS 全链路、完整宿主生命周期和最终 CI 结果仍需按最终提交分别记录。
