# M2 原始文件加密传输与落盘复核

[实施与验收](README.md) · [归档传输](m2-backup-transfer.md) · [离线源冻结](m2-offline-source.md)

本组件直接传输已打开的不可变文件，为整体备份的 Blob、元数据库文件及 OCI 归档提供通用数据对象。它复用已有加密格式、S3 客户端、两槽并发池、分片缓冲、超时和工作线程监督，不提供完整平台备份/恢复 CLI。

## 上传与重试

调用方先通过受保护存储打开文件，并提供可信元数据中的原始字节数和 SHA-256。文件必须属于 root 或当前执行用户、权限私有、只有一个链接且为普通文件；不接受任意用户路径。单对象最多 64 GiB，支持零字节 Blob。文件和归档共用两个传输槽，不各自扩张并发。

上传前须持久保存 multipart ID。文件读取、加密、网络上传均由拥有传输槽的监督任务管理，丢弃等待方不会取消工作。读取前后检查文件身份、权限、大小与修改时间；计算得到的原始明文摘要必须与可信源摘要完全相同。读取线程、加密线程和网络结果全部成功后，才调用日志回调持久保存 etag/摘要，再完成远端对象。

读取失败有时仍会使加密器产生一个合法的空对象，因此读取线程结果是独立的完成条件，不能只看加密成功。失败尽力终止 multipart，未确认的清理仍由上层持久日志跟踪。

完成响应丢失时只根据已经保存的准备记录恢复，不重新打开可能变化的源文件。即使 multipart 已不存在，也必须以精确 GET、完整 AEAD 认证和原始/密文字节摘要证明对象已正确发布。日志来源与源元数据的对应关系仍由协调器验证。

## 私有恢复

目标必须是空的、私有且未发布的普通文件。完整解密后先同步，再从头重读实际文件，核对字节数、SHA-256、文件身份及修改时间，确认后才返回文件句柄。网络和解密线程都结束后才释放传输槽。

可选的密文摘要不替代必须提供的可信明文摘要；例如 Blob 对象键可由平台快照 ID 和 Blob UUID 确定，而长度/原始摘要来自已认证的元数据库快照。AEAD 头部绑定对象 ID，最终记录完整性仍必须通过。这样顶层清单不必重复列出每个 Blob 的密文摘要。

失败可能已写入部分经认证明文，协调器必须隔离该私有文件，不能发布或覆盖旧数据。本层不会设置公开备份 ready、修改恢复门禁或启动部署；整体对象集、日志、授权与恢复仍待接通。

## 验证边界

真实 MinIO 验证零字节和 10 MiB 多分片往返、落盘重读、完成响应丢失后的恢复、错误源摘要/日志拒绝时不发布、读取失败但空对象可认证的拒绝、错误密钥/摘要的私有恢复失败及共享并发限额。原归档上传、恢复和等待方丢弃回归也重新通过。

MinIO 结果保持 `off_host=false`。这些是数据传输组件证据，不是完整平台、真实 AWS 或独立宿主灾难恢复验收。
