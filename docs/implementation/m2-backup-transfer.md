# M2 备份归档、加密与对象传输底层

[实施与验收](README.md) · [备份恢复规范](../operations/backup.md)

本增量实现宿主内部归档、加密与 S3 流式传输，不提供公开备份/恢复 API。它不会停止插件、申请一致性组、保存元数据库恢复点、切换部署卷或完成数据 Schema 迁移，因此不能作为完整 M2、全平台备份或 BACKUP-01 异机恢复验收通过的依据。

## 归档与恢复边界

`storage/archive.rs` 使用版本化记录，以先前目录 ID 和独立名称表示层级。提取用目录描述符、`openat`、`O_NOFOLLOW` 和排他创建，拒绝绝对名称、点路径、符号链接父目录、重复条目和越界硬链接。源/目标由上层提供已验证的私有卷目录；文件系统设备与 mount ID 必须一致。

记录普通文件的稀疏 extent，保留硬链接、符号链接、FIFO、许可位、限定所有者、时间及 `user.*` 扩展属性。符号链接目标仅作为数据保留，不被跟随。设备、套接字和未支持的特权/ACL 属性明确报错。每个归档最多 65,536 条目、256 层目录、64 MiB 记录元数据，单条记录最多 256 KiB。数据块最多 64 KiB；空洞不展开。恢复目标必须为空，失败可能留下部分文件，由上层隔离或清理，不能发布为可用卷。源文件和目录变动检查只能发现部分并发修改，不能替代排空和写入 fence。

## 加密与完整性

`storage/backup_crypto.rs` 使用 AES-256-GCM。每个对象以随机盐和备份/对象 UUID 通过 HKDF-SHA256 派生独立密钥；记录绑定头摘要、序号和长度，末尾必须有认证的总长度与明文 SHA-256。错误密钥、身份、顺序、标记、截断、篡改和尾随字节均不能报告成功。头只包含主密钥指纹引用，主密钥须单独离线保存。正文和临时密钥缓冲在释放时清零。

解密会在整个对象最终认证前产生已认证的早期分块，必须写入未发布目标。归档成功、解密最终认证成功、完整对象摘要匹配三项均成立，传输才返回验证结果。

## S3 与有界传输

`storage/s3.rs` 固定宿主管理的 bucket/prefix，使用 SigV4、HTTPS、受保护凭证文件、条件写入、分片上传和有界控制响应，拒绝重定向与公开任意 URL。仅标准 AWS 区域端点标记为远端后端；兼容端点即使通过读回验证也返回 `off_host=false`。这仍不能代替实际异机灾难恢复演练。

仅 GET/HEAD 在响应开始前的传输失败可最多重试两次；写入和分片完成不会自动重放。流中断和结果不明确仍交给持久任务对账。

`storage/backup_transfer.rs` 每个共享 Pool 最多两个工作流，使用管道、单槽队列和 8 MiB 分片，当前每个对象的明文归档上限为 64 GiB。更大的实际数据需要上层拆分或后续扩展，不能静默截断。归档、加密和上传并行，但归档及加密线程均成功后才尝试完成上传。完成响应丢失时只接受匹配的 GET、完整密文摘要与解密验证，不覆盖或盲删可能已发布的对象。

上层必须在开始前持久保存 multipart upload ID、预期对象身份和独占工作状态，并在传输结束前保持源停止与卷占用。丢弃等待者不会释放工作额度或取消监督任务；监督任务会等待文件线程实际退出。失败的未完成上传尝试中止，但错误或丢失响应须由持久任务继续对账，不能从一次请求失败推断已清理。目标目录的生命周期同样归上层管理。

## 验证

运行组件测试需设置 `XELAB_TEST_S3_ENDPOINT`；未设置时真实 S3 用例提前返回，Cargo 仍将它们计为 `ok`，默认输出会捕获跳过提示。向 `cargo test` 命令追加 `-- --nocapture` 可显示提示，但这不是对象存储验证。CI 通过 `tools/start-test-s3.sh` 从固定 MinIO 源提交构建隔离服务，校验所用 Go 发行包摘要，只监听 loopback，使用显式测试凭证，不继承 GitHub 令牌。测试自行创建随机 bucket 并清理自身对象；它们不访问生产资源。

本地真实 MinIO 已验证条件写入、不覆盖、分片完成与重复中止、错误凭证拒绝，以及归档→加密→上传→完整下载校验→新目录恢复。传输覆盖实际多分片、8 GiB 逻辑稀疏文件、链接保留、非空目标拒绝、生产者中途失败、最终认证失败和等待者取消后工作额度保留。加密及归档另有恶意记录、越界、截断和身份错配回归。完整 CI 结果以相应 PR 的最终提交为准。
