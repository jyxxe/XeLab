# M2 部署重建升级与同格式卷回退

[实现索引](README.md) · [升级契约](../plugins/upgrades.md) · [迁移传输](m2-migration-rpc.md)

本实现接通 upgradeDeployment / rollbackDeployment 的持久 recreate 任务，要求
同一插件/发布者的已安装可信版本。`none` 部署可无卷，也可使用匹配目标清单的卷组。
内部执行路径另外支持已经实际验证、且源/目标保持同一非 `none` 格式的卷组；
公开版本化制品安装入口仍关闭。不同格式的内部任务已接入
[私有卷格式监督器](m2-format-transitions.md)，另要求已启用 Ready 的版本化来源及
实际认证的明确可用备份；完整正向迁移和不兼容恢复验收仍未完成。
不能据此关闭 RUN-06 或宣称完整 M2 完成。
带卷宿主演练已在 PR #24 最终提交的完整 CI 41642778059 执行通过。

## 请求与授权

沿用既有请求、If-Match、Idempotency-Key 和异步 Operation，不增加客户端字段。
必须 strategy=recreate、allow_downtime=true；parallel_compatible 不属于本实现配置。
SemVer 2.0.0 优先级必须符合动作方向：upgrade 严格递增，rollback 严格递减；
不能用 rollback 权限安装更高版本。能力契约版本与插件版本独立。

事务锁定节点预算及部署，核对 Owner、当前完整来源链、plugin.upgrade/rollback、
plugin.read、plugin.enable 和目标插件读取权限。若提供 backup_id，还须匹配本部署且
当前 ready/off_host，并具有 backup.read；不改变数据格式的本配置不强制备份。
目标签名清单的配置、资源最低值、单副本和插件/发布者身份均须匹配。

先持久化原/目标安装及摘要、原/目标配置、原始实际凭证/peer/授权来源、旧实例集、
固定候选 UUID/代次和独占部署占用，再撤旧路由。幂等重放返回原 Operation，执行前
及最终提交继续检查原凭证和原来源；后来新会话或授权不能接管旧意图。

带卷重建另外要求 volume.create，以及对每个原卷和新卷 UUID 的 volume.read。
只允许读取原卷 ID 的密钥不能自动获得新卷权限。幂等重放依据原 Operation 的映射
重检两组卷及原授权来源，不会因部署已切换到新 UUID 而遗漏原卷。配额几何预检先于
节点/部署行锁，提交前重新锁定并核对原意图；所有新容量、项目号和映射一次预留。

## 运行与失败

后台监督任务最多并行两项，并与已有备份/恢复共享总占用上限。HTTP 等待结束不会
取消运行时工作。部署围栏串行化控制器与任务；取得围栏后再次撤旧路由，覆盖控制器
恰好在准入前已通过占用检查的竞态。完整配置/安装身份的变化拒绝继续，控制器的
阶段观察修订不替代授权，也不被误认成新部署意图。

实际 mTLS Drain 后停止旧实例，逐一确认运行时/cgroup 已无旧进程，才在同一预算事务
释放旧 CPU/内存并预留候选，避免中间容量被其他部署占用。Drain 未成功仍尝试全部
停止，并将任务判失败，不把强停伪装成排空。
候选继续通过原容量准入机制计账，不使用内核预留。目标引用、实际 OCI 清单及原始
plugin.json 均重新核对登记摘要；原安装已验证的签名不会被重新伪造或采用新信任。

候选在固定实例/代次上实际 Describe/Initialize/GetHealth，核对原始签名清单字节及
全部健康能力集合；整体任务、启动和 RPC 期限均有上限。只有当前授权、资源预留、
实际候选进程和健康均成立，才原子切换安装、配置、实例/提供者、Operation 并释放占用。
禁用部署保持禁用，只核对安装内容，不能据此声称已启动或健康。

版本改变会清除旧 Blob 代理批准、撤销旧 Secret 绑定并结束既有 lease；启用目标使用
空代理/出口规则，禁用目标仍需显式批准。需要这些权限时应按新版本重新批准/绑定，
不会因为升级自动扩大历史工作负载权限。

失败先停止候选和已登记旧实例，确认停止后才释放资源与占用；保留原版本/配置。
原凭证及原启用/读取来源仍有效且预留成功时，同事务创建更高代次的新原版本实例
意图，再由控制循环实际恢复；原凭证失效或不能预留时明确停用，不能留下没有实例
意图的 enabled 状态。新实例/预留失败由保存点回滚，其他清理仍可提交。占用已释放的
迟到清理不会停止新实例。停止不明确则保留占用等待重试。提交结果不明确时
先读取已持久终态，不能停止已经成功发布的新版本。

## 同格式卷组

源卷只允许由本部署挂载。持久占用阻止新的挂载/删除/扩容，正向停止证明之后才
释放旧附件、提高来源围栏并登记新组围栏。旧数据从不原地覆盖。新 UUID/项目号的
私有硬配额目录通过有界流式归档克隆，再独立读取实际目标逐项验证数据、稀疏区间、
硬链接、符号链接和元数据；归档展开完成会同步文件系统。每个目标最多 63 GiB，
卷组最多 16 项；所有阻塞读写退出后才释放占用或隔离失败项目。

候选在私有卷上通过真实生命周期和健康验证，再检查实际配额。新公共卷、候选附件、
写入围栏、挂载批准、版本、提供者和 Operation 在同一事务发布。原卷保留且不再附着。
同格式回退克隆当前卷组，包含升级后的新写入，不会直接选择某个陈旧原卷。
`none` 路径要求业务双方遵守未声明格式变化的约定，不能挂载已知版本化数据。

非 `none` 卷要求源绑定已经 Verified，且格式、插件 ID 和发布者 UUID 与双方
签名清单一致。禁用意图、部分 initializing 或只有格式标签都不能充当克隆来源。
准入、预留和停写阶段重新检查绑定；实际克隆和独立读回完成后，私有新分配才能
继承同格式证明。证明记录原卷、原证明摘要、实际复制证明及新版本清单摘要，
不递归嵌套整条旧证明，避免反复回退使日志无界增长。

这条同格式路径不执行转换；原/目标格式不同由单独的持久迁移监督任务处理。
目标还须实际 Initialize/GetHealth 后才能发布；Initialize 不能隐式改变已有格式。

进程中断后的 copying/cloned/probing 半成品不会继续初始化或覆盖：停止候选，隔离
私有分配，释放来源占用，然后依据原凭证/原读取与启用来源创建原版本新实例和
新代次挂载批准。权限或容量不足时明确禁用。隔离目录由既有卷工作器回收，保留
64 KiB 墓碑及永不复用的项目号。已成功发布的候选不会被迟到清理停止。

## 内部迁移与验证

未声明格式的卷克隆最初随 Schema 11 追加 0011_upgrade_volume_clones.sql。
格式绑定使用初始化组件追加的 Schema 12；同格式继承本身不追加或改写 SQL。
既有迁移原文与校验和保持不变。
部署占用仍以 Operation 为身份，现同时引用备份/恢复或升级任务。停机、核实备份并
确认无未完成任务后，显式执行 `xelabctl migrate --config /etc/xelab/kernel.toml --target 15`。
格式迁移的备份登记字段随[登记组件](m2-format-backups.md)追加 Schema 13；
该组件已接通格式变化执行器；同格式继承仍不依赖格式转换。当前版本另含
[恢复用户维护](m2-recovered-accounts.md)的 Schema 14 及 [HTTP 来源](m3-http-provenance.md)的
Schema 15，已发布迁移 1–14 保持不变。
旧二进制拒绝不匹配的内部版本。原生离线快照仍要求同 PostgreSQL 主版本和精确迁移布局；旧版本
快照应使用匹配的可信恢复程序，不能用本迁移伪装跨版本物理恢复。

本地真实 PostgreSQL 用例已核对失败事务回滚、ETag/停机/策略/备份拒绝、完整来源与
目标信任重检、原凭证撤销后新会话不能复活意图，以及权限失效时不提前释放占用。
新布局的原生 COPY 往返、迟到失败回滚、FK 验证与不兼容头拒绝也已验证。
