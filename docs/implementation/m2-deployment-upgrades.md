# M2 无状态部署升级与回退

[实现索引](README.md) · [升级契约](../plugins/upgrades.md) · [迁移传输](m2-migration-rpc.md)

本增量接通 upgradeDeployment / rollbackDeployment 的持久 recreate 任务。当前只接受
同一插件/发布者的已安装可信版本、`data_schema_version=none` 且源/目标均无卷的部署。
有状态 Plan/Apply/Verify、私有卷克隆/切换和不兼容数据恢复尚未接通；不能据此关闭
RUN-06 或宣称完整 M2 完成。新增宿主升级/回退演练尚待对应提交的实际 CI 验证。

## 请求与授权

沿用既有请求、If-Match、Idempotency-Key 和异步 Operation，不增加客户端字段。
必须 strategy=recreate、allow_downtime=true；parallel_compatible 不属于本实现配置。
SemVer 2.0.0 优先级必须符合动作方向：upgrade 严格递增，rollback 严格递减；
不能用 rollback 权限安装更高版本。能力契约版本与插件版本独立。

事务锁定节点预算及部署，核对 Owner、当前完整来源链、plugin.upgrade/rollback、
plugin.read、plugin.enable 和目标插件读取权限。若提供 backup_id，还须匹配本部署且
当前 ready/off_host，并具有 backup.read；无卷、无数据迁移的本配置不强制备份。
目标签名清单的配置、资源最低值、单副本和插件/发布者身份均须匹配。

先持久化原/目标安装及摘要、原/目标配置、原始实际凭证/peer/授权来源、旧实例集、
固定候选 UUID/代次和独占部署占用，再撤旧路由。幂等重放返回原 Operation，执行前
及最终提交继续检查原凭证和原来源；后来新会话或授权不能接管旧意图。

## 运行与失败

后台监督任务最多并行两项，并与已有备份/恢复共享总占用上限。HTTP 等待结束不会
取消运行时工作。部署围栏串行化控制器与任务；取得围栏后再次撤旧路由，覆盖控制器
恰好在准入前已通过占用检查的竞态。完整配置/安装身份的变化拒绝继续，控制器的
阶段观察修订不替代授权，也不被误认成新部署意图。

实际 mTLS Drain 后停止旧实例，逐一确认运行时/cgroup 已无旧进程，才释放其插件池
CPU/内存预留。Drain 未成功仍尝试全部停止，并将任务判失败，不把强停伪装成排空。
候选继续通过原容量准入机制计账，不使用内核预留。目标引用、实际 OCI 清单及原始
plugin.json 均重新核对登记摘要；原安装已验证的签名不会被重新伪造或采用新信任。

候选在固定实例/代次上实际 Describe/Initialize/GetHealth，核对原始签名清单字节及
全部健康能力集合；整体任务、启动和 RPC 期限均有上限。只有当前授权、资源预留、
实际候选进程和健康均成立，才原子切换安装、配置、实例/提供者、Operation 并释放占用。
禁用部署保持禁用，只核对安装内容，不能据此声称已启动或健康。

版本改变会清除旧 Blob 代理批准、撤销旧 Secret 绑定并结束既有 lease；启用目标使用
空代理/出口规则，禁用目标仍需显式批准。需要这些权限时应按新版本重新批准/绑定，
不会因为升级自动扩大历史工作负载权限。

失败先停止候选和已登记旧实例，确认停止后才释放资源与占用；保留原版本/配置，
正常控制循环可按当前授权恢复它。停止不明确则保留占用等待重试。提交结果不明确时
先读取已持久终态，不能停止已经成功发布的新版本。当前无卷配置没有数据覆盖；
有状态实现还须保留原卷并完成独立的备份/格式/磁盘验证。

## 内部迁移与验证

内部版本为 10，追加 0010_deployment_upgrades.sql，保留 v1～v9 原 SQL/校验和。
部署占用仍以 Operation 为身份，现同时引用备份/恢复或升级任务。停机、核实备份并
确认无未完成任务后，显式执行 `xelabctl migrate --config /etc/xelab/kernel.toml --target 10`。
旧二进制拒绝 v10。原生离线快照仍要求同 PostgreSQL 主版本和精确迁移布局；旧 v9
快照应使用匹配的可信 v9 恢复程序，不能用本迁移伪装跨版本物理恢复。

本地真实 PostgreSQL 用例已核对失败事务回滚、ETag/停机/策略/备份拒绝、完整来源与
目标信任重检、原凭证撤销后新会话不能复活意图，以及权限失效时不提前释放占用。
新布局的原生 COPY 往返、迟到失败回滚、FK 验证与不兼容头拒绝也已验证。

新增 CI 将使用真实签名 v1/v2 镜像、真实升级/回退后的业务调用与幂等重放，再以实际
启动失败的候选核对原版本恢复、停止证明与预留回收。其最终结果待记录；忽略项
不算执行通过。此检查不代替有状态迁移、正式 AWS/异机灾备或 RUN-03 宿主验收。
