# M2 离线源冻结与元数据导出

[实施与验收](README.md) · [元数据库恢复](m2-platform-recovery.md) · [镜像归档](m2-image-backups.md)

本组件为整体离线备份提供宿主会话与源冻结，不提供完整平台备份/恢复 CLI、不发布远端 ready 清单，也不放行恢复门禁。整体对象集、私有日志、远端恢复与 DataMigration 仍需接通。

## 独占与准入

会话只允许宿主管理员使用，必须明确允许停机。先获取与 `xelabd` 相同、保留至进程退出的宿主租约，再校验当前数据库和获取数据库 leader 租约；现有内核需已退出。会话互斥锁和返回值的生命周期确保同一源冻结期间不会并行修改维护状态，元数据导出也需继续持有该会话。

先拒绝未完成的备份/恢复任务、占用、分配/清理和恢复门禁，检查存在可选的独立恢复 Owner。当前最多 16 个未删除卷、128 个已安装镜像和 512 个待处理实例；卷必须完整、规格/归属/容量一致、容量不超过 63 GiB，且数据 Schema 为 none。不支持已有 Skill/Workflow/任务/调度/事件/微插件/扩展插件数据的源。

完整镜像引用来自 root 私有索引，并与安装摘要、containerd 实际 manifest 及镜像内原始插件清单逐一比对。原安装流程已验证发布者签名，这里验证持久记录所指的不可变内容，不创建新的安装或发布者信任。

## 排空、停止与同步

在实际停止前收集专用 namespace 中的容器、实例记录、挂载及插件 cgroup，拒绝未登记身份。隔离 provider，标记部署排空，然后对实际运行实例以工作负载 mTLS 调用 Drain，要求明确不再接收请求、活动调用为零且已排空。登记为运行中或持有写附件的实例若已退出，不能被当成成功排空。

随后逐个执行已有 Runtime.stop，证明 task、container、挂载及 cgroup 退出。即使某个实例排空失败，仍尝试停止其余已登记写者；只为已证明停止的实例提交停止记录、释放附件和资源。不确认的停止不退还预留，失败不产生冻结结果。

全部成功后重新检查运行时身份，分别同步平台目录与卷文件系统，再把未完成调用标记为未知并释放其并发槽，保留每日历史用量。部署保留原有启用意图，但当前阶段禁用；组件不会启动内核或重启插件。维护结束后，重新启动的正常控制器仍执行现有批准、权限、初始化和健康流程。

源冻结最多一小时。成功结果可导出一致的只读元数据流，并按持久 Root/文件系统 UUID、project ID 和实际硬配额解析卷路径。租约丢失、元数据不符或实际配额异常均拒绝。观察到的 WAL 位置仅为记录，不是连续 WAL 归档。

## 验证边界

真实 PostgreSQL 测试验证未完成任务、卷分配缺失、不支持的配置和未完成恢复的拒绝；显式停机标志拒绝测试不会接触存储。真实 OCI CI 在原生命周期验收末尾保留一个已签名、已初始化的实例，停止旧控制器并释放其数据库租约后，通过实际宿主会话冻结、核对镜像索引和导出元数据。

新 OCI 路径是否通过以最终提交 CI 为准，本地宿主忽略项不计通过。这不是完整平台备份、真实 AWS 或独立宿主恢复验收。
