# M2 全平台离线源备份与持久对象日志

[实施与验收](README.md) · [源冻结](m2-offline-source.md) · [元数据库恢复](m2-platform-recovery.md) · [原始对象传输](m2-raw-backups.md)

本阶段接通整体源备份 CLI：在独占宿主和数据库的会话中冻结源，保存原生元数据库、实际 OCI 内容、全部登记 Blob 和每个可用卷，并在全部对象远端复核完成后发布加密平台清单。完整目标物理重建、恢复门禁放行及 DataMigration 仍待完成；不能将源备份完成视为完整 M2 或灾备演练通过。

## 使用与结果

先停止管理内核，保留其宿主私有配置与独立保存的 32 字节主密钥。配置标准 AWS S3 仓库、`AWS_REGION` 和指向私有凭据 JSON 的 `XELAB_BACKUP_CREDENTIALS_FILE`；沿用既有仓库身份注册，不采用另一数据库的备份前缀。生产 CLI 不接受本地测试对象服务覆盖。

```sh
sudo xelabctl platform-backup --config /etc/xelab/kernel.toml --allow-downtime
sudo xelabctl platform-backup --config /etc/xelab/kernel.toml --allow-downtime --resume BACKUP_UUID
sudo xelabctl platform-backup --config /etc/xelab/kernel.toml --allow-downtime --cleanup-failed BACKUP_UUID
```

命令输出 JSON 回执，含备份 UUID、仓库 UUID、加密清单对象 UUID、清单明文摘要和实际 `off_host` 证据。应将回执和独立主密钥另行保存。不会自动启动内核或部署；冻结保留源部署的原启用意图，之后由操作者决定何时恢复正常内核运行。

主密钥只以指纹进入清单与本地日志，不把主密钥、宿主 HMAC、工作负载 CA 私钥或服务器私钥复制进备份对象集。若历史 Secret 指纹与当前独立密钥不符，停机前拒绝；当前流程不提供多主密钥轮换恢复。

## 源对象集与发布

停机前验证可支持的元数据、卷和镜像，检查 Blob 根身份，并物理预留最多 1 GiB 元数据库暂存空间、按实际 manifest 图计算的镜像归档空间及余量。暂存文件保持 root 私有、单链接，预留空间不提前改变文件逻辑长度。空间不足不开始 Drain。

源冻结保持到所有读取、加密和网络工作结束。元数据库使用受限的原生数据流；OCI 使用实际字节归档；最多 16 个卷使用已核对文件系统/项目硬配额的路径。最多 65,536 个登记 Blob 按其数据库 UUID、原始长度和摘要逐个读取已打开的受保护文件，不复制整个 Blob 目录，也不把未登记孤儿纳入备份。

元数据库、OCI、卷及清单分配互不冲突的对象 UUID；Blob 对象 UUID 等于其原 UUID。恢复可从认证元数据库的 Blob 行推导固定对象键，无需在 1 MiB 清单内展开数万条目。原始文件与卷归档共用两个传输槽。

清单校验包括精确 Schema 版本、元数据库原始摘要/长度与 LSN、安装引用和 OCI 内容对应、卷规格/容量/文件系统/项目号、候选恢复 Owner、对象 UUID 唯一性及完成证明。LSN 是停止后观测点，不是 PITR。只有全部对象远端长度、SHA-256、AEAD 和归档证明完成，才条件写入加密清单并 GET 解密复核；中间密文对象不构成完整备份。CLI 不把它伪装成部署备份 API 的 ready 行。

## 日志、恢复与失败清理

每个新备份独占 `.platform-backups/BACKUP_UUID`，通过目录描述符、无符号链接打开、私有权限、独占文件锁、原子替换和文件/目录 fsync 持久化状态。禁止复用已有会话目录。

每次 S3 initiate 前先保存 starting 意图；拿到上传 ID 后先落盘再读取源；全部生产者成功后先保存 prepared 分片/摘要，再 Complete；远端校验后保存 verified。发布清单前另存 committing 检查点。阶段不能回退或跳过，终态不可改写。

只有全部源对象已经 prepared，才允许断点恢复。恢复只根据原保存的上传身份和摘要完成或重新 GET 认证，不重新读取可能已经恢复运行的源，避免混合两个时间点。缺少任一 prepared 的旧对象集不能继续补读。清单完成但回执响应丢失时，重复恢复核对既有清单并返回原回执；成功后只删除两个已知明文暂存文件。

失败清理只接受 failed 会话，按保存上传 ID 和该会话精确对象键扫描/中止 multipart，不删除已完成对象、清单或本地证据，不触碰相邻前缀。starting 意图可发现丢失 initiate 响应的上传。意图永久保留，回执明确需要后续重复扫描，以捕捉延迟出现的上传；一次空扫描不证明永久清理完成。对尚未进入发布阶段的中断会话，恢复检查若发现源准备不完整，会将其持久标为 failed，再允许清理；不会从新源补齐。committing 记录不完整则保留证据并拒绝，不误标为可清理的失败。

## 验证边界

本地回归使用真实 PostgreSQL/MinIO 检查完整对象集才发布、错误密钥不发布、删除源文件后按 prepared 恢复、精确键清理、丢失/延迟 initiate 响应、相邻上传保留、日志重开/竞争/损坏拒绝及清单语义一致性。组件夹具中的模拟元数据不当作原生快照验收。

宿主 CI 在真实签名 OCI 生命周期之后，经正常离线会话冻结源并调用同一捕获驱动，上传实际元数据库、镜像和 Blob，从远端加密对象重新导入新的 PostgreSQL，逐 Blob 解密重读；目标物理恢复未完成时，验证数据库门禁继续拒绝启动。该兼容对象服务始终 `off_host=false`。新增宿主路径是否通过以最终提交 CI 为准，本地忽略项不计通过；仍不等价于真实 AWS、独立机器完整恢复或 RUN-03。
