# M2 私有卷格式迁移监督器（验收中）

[实现索引](README.md) · [部署重建](m2-deployment-upgrades.md) · [备份登记](m2-format-backups.md)

本增量把已登记版本化插件的格式变化接入持久升级任务：升级使用私有当前数据克隆，
不兼容回退使用目标旧版本的备份恢复。公开版本化制品安装入口仍关闭。
正式 AWS 可用备份下的完整正向迁移、回退与内核死亡演练尚未验收，不能据此关闭
RUN-06 或宣称完整 M2 完成。该组件最初使用 Schema 13；当前内部版本为 14，
已发布迁移 1–14 及其校验和保持不变。

## 准入与原意图

只接受已启用且 Ready 的版本化来源、同插件/发布者的可信已安装目标、recreate 和
显式停机。源/目标都须为非 none 格式；不同格式必须明确提供同部署的可用备份。
升级备份必须精确对应当前来源安装；不兼容回退备份必须对应目标旧安装。
登记检查及实际仓库、AEAD 清单、完整摘要和 off_host 证据见备份登记组件。
兼容存储保持 off_host=false，不能为测试或准入改写成正式可用备份。

当前来源卷、私有目标 UUID、独立临时项目以及备份中的历史源卷 UUID 均保留各自
权限。任务保存实际原凭证/主体/peer/授权来源；新会话和后来授权不能接管。
最多 16 项业务卷与额外 64 MiB 临时项目分别预检几何，在同一预算事务预留，
随后保存父重建任务和同 Operation 的子格式任务。公开部署仍指向原安装及原卷。

子任务每阶段核对父任务动作、部署、候选实例/代次、原凭证与授权快照、目标安装/
配置/卷选择、源/目标格式、备份 UUID、统一围栏及精确期限；再核对私有卷的
Owner、操作、根文件系统、项目号和规格。初始化任务仍由独立 bootstrap 监督器
拥有；格式变更子任务只由父重建监督任务执行，不会被两个监督器并发处理。

## 升级与写入检查点

1. 既有重建流程排空并正向停止所有原写者，释放旧附件并同事务转移候选预算。
   当前数据复制到新私有 UUID/硬配额项目并独立读取核对。此时继承的是已验证
   **来源格式**，复制结果不能把格式 1 重命名成格式 2。
2. 候选业务挂载只读，临时项目单独可写。实际 Describe 核对原签名清单字节，
   Plan 保存稳定 ID/摘要；必须要求独占写，且临时容量不超过 64 MiB。
3. 停止只读候选，实际比较冻结私有克隆与所选可用备份。旧备份若漏掉当前写入，
   任务失败并保留原数据。比较只处理私有目录，避免归档核对的时间元数据操作
   影响公开来源。所有传输/文件工作均等待实际结束。
4. 在任何可写启动之前，原子保存 Applying 和目标格式 initializing 意图，再以
   原计划、备份 UUID、围栏发送一次 Apply。成功、错误、断连或未知结果均先停止
   可写候选，再以只读业务挂载执行原计划 Verify。
5. 重启后 Applying/Verifying 直接停止旧候选并只读 Verify；不会重克隆、把已转换
   数据与旧格式备份再比较，或重发 Apply。检查点已保存而写入尚未发生时也不能
   猜测重放；验证不通过则隔离私有结果并恢复原版本意图。

Verify 的实际目标格式/计划/围栏证据先绑定私有分配。随后确认仍带临时挂载的
候选已停止，以同一实例/代次重建不含临时目录的可写运行时，激活已确认格式并
核对全部能力健康。只有这条实际路径才能构造不可反序列化的发布凭据。

## 不兼容回退与原子发布

不兼容回退把所选旧安装备份解密、恢复并独立读回至新的空私有项目，不克隆当前
新格式卷，也不要求 Apply 执行逆转换。复制/恢复的 Copying 检查点先于文件写入；
中断半成品不能覆盖重试。恢复完成后由旧版本只读 Plan/Verify 确认实际目标格式。
备份历史 UUID 按别名映射至新 UUID；容量可以保留当前已扩大的额度。

回退结果对应所选旧备份时点。当前新格式原卷完整保留，之后的新格式写入不会
自动逆转或合并进旧格式结果。同格式回退仍克隆当前卷组，保留升级后的当前写入。

最终短事务再次检查原授权、父子意图、私有格式证明和部署围栏，再一起发布新卷、
附件/单写者、安装/配置、实例/提供者、Operation 和子任务终态，并隔离已实际脱离
运行时的临时项目、释放占用。没有实际验证和健康凭据不能发布；事务失败全部回滚。

失败先正向停止全部原实例及候选，并等待文件工作退出，再隔离私有目标和临时项目。
原格式公开数据保留；原凭证仍具备原版本读取/启用权限且能预留资源时，建立更高
代次的新原版本实例意图，否则明确停用。备份或目标权限失效不能替代原版本权限，
也不能阻止仍有合法权限的原版本恢复。停止或围栏不明确时保留占用。

## 验证状态

本地真实 PostgreSQL 已验证父子绑定、私有卷和历史备份 UUID 的完整原授权组合、
原凭证撤销、已有升级/同格式绑定和初始化检查点回归。数据库夹具没有预置可用
off_host 备份或物理 Verified 格式；它们不证明完整运行时迁移。
既有真实 mTLS/磁盘协议用例验证写后结果未知时只 Verify、不重发 Apply。

新增特权用例构建实际签名格式 2 目标，从正在服务的格式 1 部署请求无备份升级，
要求在分配、占用及写入前明确拒绝，保留原字节和写者，并继续完成真实业务写入。
该拒绝路径已在 [PR #29 最终完整 CI](https://github.com/jyxxe/XeLab/actions/runs/41754772496)
实际执行通过；它不能当作成功转换证据。[真实 AWS 演练入口](m2-aws-format-acceptance.md)
已随 PR #34 合并，默认完整 CI 通过，但其中 AWS 正例因缺资源明确忽略，尚未执行。
正式可用 AWS 备份下的完整父任务升级/回退、迁移中内核死亡与 RUN-03 独立宿主
仍是未完成验收，不通过弱化 off_host、权限或格式证明来补齐。
