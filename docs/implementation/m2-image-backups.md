# M2 实际 OCI 镜像归档与空内容库导入

[实施与验收](README.md) · [元数据恢复](m2-platform-recovery.md) · [加密传输](m2-backup-transfer.md)

本组件为全平台离线恢复保存实际 OCI 内容，不只保存镜像名称或摘要。尚未接通整体备份/恢复 CLI、远端镜像归档对象或恢复门禁放行，不能作为完整 M2、真实 AWS 或异机灾备验收通过的依据。

## 归档与验证

只接受 1～128 个按序去重的不可变 SHA-256 引用。源镜像需已存在于配置的专用 containerd namespace，并通过现有固定平台 manifest 校验。通过受信宿主 `ctr` 导出标准 OCI 归档，跳过 Docker `manifest.json` 兼容文件；子进程清空继承环境，使用固定参数，不运行 shell。

输出必须是空的、root 所有、私有权限、单链接普通文件，协调器负责暂存空间预留及后续加密。归档最大 64 GiB，复制缓冲为 64 KiB，保存完整长度/SHA-256 并同步落盘。组件调用限时五分钟；失败或超时终止并等待子进程退出。

归档以严格受限的 OCI USTAR 格式读取，不向文件系统提取 tar 路径。只接受 OCI layout、index、SHA-256 blob 和两个固定目录；拒绝路径越界、链接、特殊条目、重复 blob、未知 tar 格式、头部校验损坏及异常尾部。最多 65,536 个条目，单个 JSON 最多 2 MiB、保留 JSON 合计最多 16 MiB。

逐个重新计算所有 blob 的 SHA-256，再核对 index 覆盖请求的镜像，以及每个镜像 manifest 引用的 config/layer 摘要和实际尺寸。缺失层、错误尺寸、外部 URL 或嵌入内容均不能通过。不依赖源 containerd 内容库仅以摘要命名就假定字节正确。

## 私有导入

目标 namespace 必须没有容器或镜像。先完整核对暂存文件长度、摘要、OCI 内容和引用图，再从头导入；导入同时重新计算实际传入的字节摘要，并检查文件身份、大小和修改时间未变化。使用 `--no-unpack`，不启动工作负载，最后逐个核对目标镜像固定摘要。

失败后保留未发布 namespace 供协调器检查，不删除共享 containerd 内容、不自动启用部署、不放行平台恢复门禁。协调器仍须独占宿主/数据库、证明所有写者退出、预留目标空间，并在镜像与卷/Blob/元数据库整体校验后完成恢复。

## 验证边界

本地字节级测试覆盖实际 OCI tar 结构、blob 损坏、缺失 config、layer 尺寸不符、截断、尾部数据、越界路径、链接、传输限额和不可变引用限制。真实宿主测试另外启动一个具有全新 root/state/socket 的独立 containerd，导出实际镜像再导入空内容库，并核对错误摘要不导入、成功后镜像摘要一致及拒绝非空目标。

该宿主测试仅操作自建临时目录和独立 daemon，不删除原 daemon 镜像或共享内容。当前是否通过以最终提交 CI 为准，本地忽略项不计作通过。独立内容库组件验证仍不等价于独立机器灾难恢复。
