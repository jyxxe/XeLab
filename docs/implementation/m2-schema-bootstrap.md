# M2 业务格式初始化监督器（开发中）

[实现索引](README.md) · [迁移 RPC](m2-migration-rpc.md)

本分支加入首次格式初始化的持久准入和守护进程监督器，非 `none` 制品入口继续关闭。
格式升级、按目标版本备份回退及实际 OCI/XFS 故障恢复验收尚未完成，不能据此宣布
完整 DataMigration 或 RUN-06 验收通过。格式初始化使用追加的 Schema 12，
不修改迁移 1–11 的内容或摘要；旧快照仍需匹配布局的恢复程序。

已登记安装及运行时制品共用内部格式执行校验；公开 `Artifact::inspect` 仍使用
关闭版本化格式的安装校验。内部格式配置仅允许独占可写部署卷、recreate、
无代理权限请求和非流式 `none`/`idempotent` 能力；不能用它开放扩展或其他副作用。

## 准入与格式绑定

现有部署必须先禁用创建、显式审批，再请求启用。监督器保存该次 Operation、
原凭证/主体/peer/授权来源、不可变安装元数据、部署配置、固定实例和代次。
业务卷完整分组与独立 64 MiB 临时项目同时纳入配额准入，持久部署/卷 hold 在
任何可写初始化之前提交。CPU/内存预留在同一预算事务内更新启用意图之后执行。

`unversioned` 只是没有已验证格式的元数据；不能据此宣称卷为空。
监督器持有真实部署运行时围栏，确认旧实例和遗留挂载对应的进程全部停止后，
检查实际 XFS 命名空间、项目号、硬配额和数据目录。只有实际空的未知卷才绑定
`initializing` 意图。已有部分初始化必须属于同一部署和原清单摘要；其他插件、
发布者或格式不能复用这个意图。Schema 字符串不是跨插件的全局格式标识。

非 `none` 启用要求完整 `verified` 绑定；`none` 清单也不能挂载已知版本化数据。
`verified` 需要实际 Verify 成功的证明，不能从健康检查或 Schema 字段直接推断。
初始化中的卷不能进入普通备份或全平台源导出；全平台恢复会终止旧未完成意图。

## 执行与恢复检查点

守护进程最多同时拥有两个初始化任务。所有运行时变更都由拥有围栏的任务执行，
不依赖 HTTP 等待者；阻塞文件系统检查始终等待完成后才进入清理。

1. 核对实际 OCI 内容及 Describe 原始字节，业务目录只读挂载，临时目录单独可写。
   Plan 使用稳定操作键；计划 ID/摘要、临时容量和分组写围栏持久化后才能继续。
2. 确认只读实例停止，持久化 `initializing`，然后才能创建可写实例或调用 Initialize。
   初始化请求结果不确定或内核重启时，先以只读业务挂载对原计划执行 Verify，
   不能重复未知写入；首次初始化调用后同样停止可写实例，再只读核对结果。
   一个新的显式请求可以验证同一绑定的部分初始化；验证失败时保留数据、禁用部署。
   如果写入前失败留下的绑定仍对应实际空目录，新请求在取得停止围栏并重新检查空目录后
   可保存空卷证明并初始化；旧操作不因此重发未知初始化，非空部分数据仍必须先 Verify。
3. Verify 必须确认实际目标格式、原计划及围栏。随后确认临时目录仍挂载的实例停止，
   以同一实例/代次重建不含临时目录的运行时，激活已确认格式并检查全部能力健康。
4. 最后重新核对原授权、配额、配置和围栏，在一个短事务内发布格式证明、挂载、
   单写者、提供者、部署/实例就绪和原 Operation 结果，再释放 hold。
   临时项目仅在其挂载实例已停止并脱离后隔离，由卷回收器检查实际归零并回收容量。

任何失败先确认相关进程全部停止，再释放资源、禁用原意图、隔离私有临时项目并
完成失败操作。业务数据及 `initializing` 绑定保留，不能重命名成其他格式或清空。
停止证明缺失、运行时围栏或领导权丢失时保持 hold，留待下一位持有者恢复。
新登录或后续新授权不能替换原任务保存的凭证及授权来源。

## 幂等业务调用

内部格式执行路径允许清单中明确声明的幂等能力。提供者必须满足版本化配置，
其契约摘要、输入/输出/流结构和副作用声明必须与登记契约一致；普通 `none`
格式清单不能借用这个入口声明幂等写入。公开安装入口仍关闭。

调用沿用提交 RPC 前持久化 Call 和幂等记录的路径。结果不确定时，重放相同键只
返回原 Call 的 OUTCOME_UNKNOWN，不重新派发；相同键更换输入仍冲突。未确认
调用的配额槽位保留到实际运行时围栏清理，当前调用权限也必须在重放前重新检查。
这不是重新发送写入来猜测旧调用结果的机制。

## 当前验证范围

本地检查包含实际 PostgreSQL 的持久检查点约束、资源预留顺序和原授权回放检查，
以及幂等调用结果未知时的日志/配额/重放检查、原有元数据恢复和普通 `none` 路径回归。
调用测试使用没有实际运行时的提供者元数据，派发按真实错误路径记为 unknown；
没有据此声称实际业务写入。数据库行是元数据夹具，不是实际
文件格式、XFS、进程停止、异机可用备份或公开迁移入口的证明。

签名 OCI/XFS 的初始化、进程死亡和失败清理验收，之后才能考虑开放制品入口。
