# M4 持久化事件与投递

[实施索引](README.md) · [事件语义](../tasks/events.md)

## 实现范围

事件发布、订阅创建/读取/分页/停用、SSE 拉取和确认沿用公开 v1 契约。
主题必须出现在已安装、当前受信插件的签名清单中，位于 `plugin_id.` 命名空间，
主题版本的 Schema 摘要和内容不可漂移。Schema 摘要使用与 Skill 定义相同的
RFC 8785 规范化和 I-JSON 数值约束；发布载荷另按该 Schema 校验，最多 1 MiB。

发布事务同时写不可变事件、24 小时去重记录和专用 outbox 意图。
后台控制循环按顺序、每批最多 64 条使事件可见；重复处理同一意图不复制事件。
返回发布成功表示已持久接收，并不表示消费者已收到或完成副作用。
去重范围是发布账户、精确主题、版本和 dedupe_key；相同键但载荷不同返回冲突。
载荷先由 PostgreSQL JSONB 规范化，再以保留数值精度的确定性 JSON 序列化
计算指纹与存储计账，避免大整数合并及负零/指数形式在备份往返后产生漂移。

序号分配、发布、latest 水位和投递在同一核心存储锁下排序。
序号为显式 bigint 和事务计数器，提交前崩溃不会留下可跨越的未提交水位，
备份导入也无需恢复数据库序列。公开 cursor 仍是最近确认的事件 UUID。
latest 排除创建前已接受但尚未从 outbox 可见的事件；earliest 从可保留事件开始。

## 租约、安全与故障

每个活跃订阅最多一个未确认租约，期限 30 秒。令牌使用随机 256 位秘密，
数据库仅保存摘要。断线、未读取响应体和进程结束均不自动确认。
事件授权对象是全局主题，owner 为空；必须显式授予精确主题 ID 或 all。
owned_by 不匹配主题，不因拥有订阅或发布账户而获得主题载荷访问权限。
显式主题授权允许读取该主题下不同发布账户的广播事件，不能把 publisher_id 当租户过滤器。
所有读取和确认另校验订阅归属、当前消费者凭证、授权源链及祖先链。
订阅创建时的凭证、来源、peer 和可信 Origin 作为审计元数据保留；
同一账户可使用当前获准的新凭证续用持久游标，订阅寿命不绑定旧交互会话。
可读取停用元数据供审计，停用后禁止投递和确认。

同一已成功 ack 的合法租约重复确认成功；过期租约即使尚未接管也返回冲突。
重投生成新 delivery_id/令牌，旧消费者不能推进新游标或改变其结果。
retry 持久保存 1/2/4/8/16 秒指数退避及至多 25% 抖动，上限 60 秒；
达到 maximum_attempts 或显式 dead_letter 时写死信及原因，再推进游标。
死信通过 event_dead_letters 和事件审计记录核查，不增加未定义的公共管理端点。
消费者须使用 event_id 或自身业务幂等键防止重复副作用。

SSE 直接由响应体拉动，不后台排队载荷；每次领取前恢复当前凭证和完整授权来源。
连接最多一小时，30 秒慢消费者截止；全核心最多 32 个事件 SSE 连接，
15 秒无业务时发送注释心跳。丢弃响应体终止轮询，并保留已领取租约等待重试。

## 保留与边界

事件保留 7 天，死信保留 30 天；活跃订阅的未确认积压保留至终态。
核心 event_store_limits 对所有事件实施 256 MiB 载荷及信封计账上限、
100000 条事件、200000 条投递历史和 1000 个订阅的全局上限。
达到上限拒绝新发布/领取/订阅并记录容量告警，不静默丢失事件。
保留期清理删除过期去重、已终结历史和不再被活跃订阅引用的事件。
cursor_sequence 保持位置，因此删除已确认事件不会让游标倒退。

不提供外部 webhook 推送，不引入 M5 工作流或 M6 SDK。AWS 继续 DEFERRED；
正式 daemon/宿主重启和独立宿主生产验收仍由 [#50](https://github.com/jyxxe/XeLab/issues/50) 跟踪。
实际 PostgreSQL、事务回滚、组件进程 SIGKILL/reexec 和公开 SSE 的执行证据
由阶段 PR 与最终 M4 验收记录补齐，不能替代 #50 的正式生产证据。
