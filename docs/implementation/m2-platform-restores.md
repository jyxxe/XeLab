# M2 全平台目标恢复、物理重建与门禁

[实施与验收](README.md) · [全平台源备份](m2-platform-backups.md) · [原生元数据库与身份隔离](m2-platform-recovery.md)

本阶段接通目标恢复 CLI：从认证平台清单恢复元数据库、实际 OCI、全部登记 Blob 与卷，在全部物理内容和新 Owner 权限验证后原子放行数据库恢复门禁。部署仍保持禁用，旧授权不恢复，命令不启动内核。新增完整宿主路径是否通过以最终提交 CI 为准；生产 AWS、独立机器演练和 RUN-03 仍须各自取得证据。

## 命令与目标要求

```sh
sudo xelabctl platform-restore --config /etc/xelab/kernel.toml --receipt-file /root/platform-backup.json --owner-id OWNER_UUID --source-host-fenced
sudo xelabctl platform-restore --config /etc/xelab/kernel.toml --receipt-file /root/platform-backup.json --owner-id OWNER_UUID --source-host-fenced --resume RECOVERY_UUID
```

新恢复 Owner 密码从标准输入读取；不得等于该 Owner 在源快照中的旧密码。候选 Owner 必须是清单及元数据库中已存在、未归档的独立根用户，保留原账户 UUID、资源归属与树，不伪造账户创建时间。回执文件要求当前 root 所有、0600、单链接；保存源备份回执时应使用私有权限。

操作者先独立隔离旧宿主，并明确传入 `--source-host-fenced`。目标须使用可信当前 Schema 的空 PostgreSQL、root 私有的全新存储根和空专用 containerd namespace，无存活实例或遗留插件 cgroup。源存在卷根时，需新的专用、空 XFS 文件系统，UUID 与源不同；当前仅接受 `none` 数据 Schema。恢复限于相同 PostgreSQL 主版本和精确迁移/列布局，不执行输入中的 DDL，也不自动升级插件数据。

主密钥从单独恢复的 32 字节私有文件读取；HMAC、工作负载 CA 与服务器私钥由目标独立配置。仓库只读打开：标记必须已经存在且精确匹配源仓库 UUID，不在空目标数据库注册或创建一个新仓库身份来冒充源。生产 CLI 沿用标准 AWS 配置，不接收测试对象服务覆盖。

## 数据与权威隔离

宿主与数据库租约全程独占。数据库 `importing` 门禁在写入任何目标数据前提交；当前及此前支持此 Schema 的内核均须拒绝非 ready 恢复状态。私有日志绑定原回执、认证清单、目标目录设备/inode 和运行时 socket/namespace，拒绝换目标目录或混用快照。

原生元数据库通过完整密文认证、原始摘要及实际落盘重读后导入。所有旧凭据、密码、授权来源、OAuth、委派、Secret 绑定、发布者信任和挂载审批失效；只为新密码的恢复 Owner 创建有真实新时间戳的恢复锚点。其他账户保持禁用或原归档状态，每日用量保留；全部部署禁用，实例停止，未完成调用/任务不重放。此时门禁只到 `rebuilding`。

OCI 导入前验证完整归档和精确名称到摘要图；导入后重读所有 CAS blob 并核对完整镜像清单。重试只允许目标 namespace 已有已授权引用的子集，仍重新认证归档、读取全部内容；未知别名或已有损坏内容不能通过。重建私有镜像索引后，再挂载核对原始插件清单摘要及 profile，不把内容验证当作发布者重新信任。

Blob 保留原逻辑 UUID，从认证元数据库的原始长度/SHA-256 推导对象键。先记录并绑定新的物理 Blob 根 UUID；解密写入预留空间但逻辑 EOF 为空的私有暂存文件，AEAD、摘要和重读通过才按 UUID 发布。已完成文件在重试时重新读取验证，错误字节不被覆盖掩盖。兼容对象服务的证据始终 `off_host=false`。

## 卷预留与发布

逻辑卷 UUID、规格和所有者保留，物理根 UUID、文件系统 UUID、项目号更新。项目号从已推进源高水位的永久序列分配，不回收旧号。先依据目标实际块/inode 几何计算全部容量、元数据开销和历史 tombstone 预算，持久化整个新映射，再在短事务内重绑定根及分配行。

只临时延迟可信当前 Schema 中固定的根外键，完成父子标识切换后立即验证并恢复原非延迟规则；迟到错误回滚全部修改。重建时分配行保持私有恢复状态，数据库总门禁仍关闭。文件操作、S3、解密和配额检查均在该事务之外。

每个卷使用正确命名空间与实际硬配额的私有目标，解密/解包之后对实际磁盘再次完整验证。已完成目标只重验；未完成目标在全部旧工作线程已退出的独占恢复会话中，才可清理自己的 data 子目录并重建，保留 UUID 目录、项目号、硬配额和根标记。不得覆盖已发布数据或删除源卷。

最后重新读取 OCI、所有 Blob 和卷归档对应的实际磁盘内容，检查硬配额/用量及完整映射；实际登录新 Owner 并验证权限，验证登录放在回滚事务内，不留下测试会话。再以短授权事务核对门禁、旧权威仍失效、无写者和旧预留，发布新卷绑定/用量/新 fence，并将门禁原子设为 ready。完成后仅删除两个固定明文暂存文件。

## 中断与验收

协调器拥有后台监督任务及共享两个传输槽。调用方丢弃等待不会取消内部工作；进程死亡则由操作系统结束所有线程和文件描述符，永久宿主租约在进程退出前不会释放。重试重新获取宿主/数据库和日志独占锁，只按原恢复 UUID 继续；导入事务提交结果不明时以数据库门禁和原摘要判定，不重新设置旧密码或复活旧凭据。

初始化门禁已提交但日志头尚未完成的窗口，只在可信元数据库完全为空、运行时和目标仍全新、日志目录仅有空 intents/自身写入临时文件时重建日志头；任何数据文件、未知对象或另一个会话均拒绝。已完成恢复重复返回原回执，不重新初始化数据。目录设备/inode 或运行时身份变化时保留门禁并拒绝，不能自动采用另一个物理目标。

本地真实 PostgreSQL 回归覆盖完整根/分配原子切换、迟到失败回滚及外键规则还原；文件回归覆盖初始化日志中断、载荷/链接/竞争拒绝、实际空间预留且 EOF 为零、原始摘要和引用限制。新增宿主演练以实际源 XFS 数据卷、原生元数据库、OCI 和 Blob 生成对象集，移除测试源卷，再以全新数据库/内容库/XFS 与独立密钥配置恢复；数据重建后实际终止子进程，重试后故意损坏目标数据验证门禁拒绝，修复测试字节后才验证完成。用例尚未在最终 CI 完成前不得计为通过，亦不等价于独立机器或 AWS 验收。
