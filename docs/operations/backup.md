# 备份、恢复与销毁

[文档总目录](../README.md)

> 规格版本：2.8.0；状态：待实现的规范性设计。MUST/必须表示实现及验收要求，不能理解为现有功能。

## 一致性备份

先验证 backup.create、部署和卷范围，停止新写入并排空/冻结数据，记录元数据库一致性点与各卷数据 Schema 版本，生成清单摘要后复制到宿主外存储。只有校验完成才 Backup.state=ready。

备份清单必须包含 backup_id、deployment_id、installation digest、data_schema_version、卷 ID/容量/摘要、元库恢复位置、创建者、时间及加密密钥版本引用。密钥引用不是主密钥明文。

并非所有数据库都可用文件拷贝在线备份。插件需通过排空/迁移协议建立一致性点；不能仅对运行中单写卷拷贝文件后宣称可恢复。

## 恢复

restoreBackup 必须明确 allow_downtime。先停止目标写入，恢复到新卷，验证摘要和数据格式，完成受控切换后才恢复路由；保留原卷，避免错误恢复不可撤回。元库恢复后重新验证凭证、宿主密钥版本与当前运行实例，执行完整对账。

宿主密钥需独立离线保护备份；只有数据库备份而没有可用主密钥无法恢复 secret。恢复不会复活历史已吊销凭证；需保留最新撤销/审计水位或统一废止旧凭证并重新签发。

## 保留与销毁

部署禁用、程序卸载不销毁数据。卷销毁要求独立权限、ETag、显式确认 ID，且未挂载、不被恢复操作占用。备份过期按明确保留策略和审计清理，默认不随插件卸载删除。

本版备份后端连接由宿主管理，公开 API 只能选 off_host，不能传任意路径或 URL 让服务写入。具体对象存储适配器属于运维实现，不成为第三方插件的宿主文件访问接口。

微插件备份同时包含核心微版本元数据与私有源码制品对象；prepared_handle、运行中VM和MPR编译缓存不备份。恢复先核对包/源码摘要和固定runtime安装，再重建微部署准备状态，不把旧句柄当活绑定。
