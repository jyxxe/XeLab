# 统一授权算法与撤权

[文档总目录](../README.md)

> 规格版本：2.6.0；状态：待实现的规范性设计。MUST/必须表示实现及验收要求，不能理解为现有功能。

## 决策输入

输入为已验证 AuthContext、action、实际资源记录、环境（时间、peer、audience）及可选执行委托。资源 owner、父级、版本来自数据库，不能从客户端正文采信。

## 固定顺序

1. 验证凭证摘要、到期和 revoked 状态，得到 subject、source_credential、client 和工作负载。
2. 追溯账户祖先及全部源委托；任一节点失效即拒绝，检测循环或缺记录即 fail closed。
3. 展开当前角色和固定组版本的有效来源，在同级求并集。
4. 按层与 selected/snapshot/follow 上限、时间、来源、audience 和系统边界求交。
5. 用户代理执行再与实际插件获批代理权限、固定执行委托和目标资源策略求交。
6. 对目标 ID 做对象级判断，列表也过滤不可见对象；读取不可见资源返回 404，已知主体操作越权返回 403。
7. 在发生副作用前确认当前 authz_revision 与对象 revision；写操作把授权版本检查和状态变更纳入同一事务。

决策函数返回 allowed/code/authz_revision。authorization/check 只是提示，执行接口必须重新判断。代码不得仅在网关检查而允许内部任务入口绕过。

正常用户的最小身份自助动作按 [角色规则](roles.md)作为固定系统来源判断，不因只选择部分业务继承而被抹去；仅作用于本人/合法后代，并继续检查状态、源凭证非动作条件和额度。Key 不补齐此来源，必须与其实际动作上限求交。签发任何下级业务权限时仍严格应用全部父级与源凭证的业务上限，不能借自助接口创建更宽授权。

## 单节点缓存

每次授权变更在同一事务递增受影响主体/策略版本并写 outbox。核心模块订阅失效通知；通知漏失由每次受保护请求读取当前版本纠正。无法确认当前版本或数据库状态时拒绝敏感动作。

撤权事务提交后，新调用和后续任务步骤不能再使用旧授权。已开始外部副作用无法凭权限撤销自动撤回，按任务核实/补偿处理。已 revoked 的凭证永久终止；仅祖先暂时 disabled 的链可在祖先恢复后重新计算有效性。

## 服务执行

run_as=service 需要单独批准的服务主体和操作范围。调用者无权时不能自动切换成服务账户。内部读取绑定密钥是服务内部授权，不要求普通用户获得 secret 原始读取权限。
