# 子账户继承与源凭证链

[文档总目录](../README.md)

> 规格版本：2.8.0；状态：待实现的规范性设计。MUST/必须表示实现及验收要求，不能理解为现有功能。

## 继承选择

| mode | 固定上限 | 父级新增权限 |
|---|---|---|
| selected | 选定规则与固定组版本展开结果 | 不自动扩大 |
| all_snapshot | 创建时全部有效权限 | 不自动扩大 |
| follow_parent | 取父级实时有效权限 | 显式同步扩大 |

创建默认建议 all_snapshot；API 必须明确传 mode，避免客户端隐式选错。所有模式都在每次请求时与父级当前权限求交；收权始终有效。上限包含动作、资源与条件，而非仅动作名称。

此处继承集合描述可选业务与管理授权。子用户的固定最小身份自助规则见 [角色](roles.md)，由创建用户动作一并建立；创建更多主体只能继续派生当前有效业务上限。账户/祖先禁用、源凭证到期、来源网络和树额度等强制条件对自助操作仍有效，不能利用基本自助能力解除它们。Key 的授权集合不享有自动补齐例外。

## 账户树

账户只有一个 parent_id。创建时锁定全部祖先额度，验证无环和最大深度。父关系不可通过普通更新修改；归档父账户保留 tombstone，不能使后代成为根。

父级可以在当前可授范围内调整下级上限；下级不能改变自身或祖先上限、独立根属性或源委托引用。直接角色绑定同样要经过完整上限求交。

## 资源所有权

own 在签发时转换成明确 ResourceSelector 和 ownership_rule。继承父级某个卷的读取授权是一次明确的数据授权；仅创建父子关系不自动授权双方读取所有数据。

子账户自己创建的新资源记 child owner_id。创建权限的 owner 范围由内核按“允许为自身/获准后代创建”的独立规则核对，不能把父级 existing-owned 数据范围悄悄替换为任意 owner。父级读取新子资源仍需明确的后代资源授权。

## API Key 再派生

用 K1 创建 K2 或子账户时，保存 K1 为 issuer_credential_id；K2 的范围、到期、来源条件以及后续有效性均受 K1 限制。K1 过期或吊销使此链失效，即使目标主体本身有更宽权限。

正常登录会话下创建长期凭证，授权来源是账户；单个会话退出不撤销新凭证。平台必须区分普通交互会话与受限委托，不能通过重新换会话洗掉 API Key 来源。

树配额独立于权限集合；follow_parent 不会自动复制父级额度。例：A 读写 → B selected 只读 → B 的 all_snapshot Key 仍只读。
