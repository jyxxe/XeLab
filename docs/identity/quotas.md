# 账户树配额与并发

[文档总目录](../README.md)

> 规格版本：2.8.0；状态：待实现的规范性设计。MUST/必须表示实现及验收要求，不能理解为现有功能。

## 默认值和单位

初始建议：最大深度 4 层、后代账户总量 20、有效 API Key 总量 50、并发调用 16、每日调用 10000。它们是可配置初始策略，不是性能承诺。根深度计为 1，所有祖先同时累计使用。

daily_calls 使用 UTC 自然日；终生 max_calls 则按密钥记录累计，不能通过自然日重置绕过。有效 Key 数包含当前树内 active 且未到期的 Key；归档和过期通过事务维护计数。

## 原子准入

创建子账户/密钥按根至叶锁定账户及配额行，在同一事务校验并扣增所有祖先。调用并发通过带 TTL 的 reservation 占位，完成或崩溃对账时释放。每日计数在业务被接受时扣增，拒绝授权不计入业务使用量，但安全限流另算。

任何请求必须满足所有祖先额度和密钥自身额度；下级配置不能比祖先更宽。修改额度低于当前使用量返回 409，不自动删除已有主体。分页查询不是绕过额外对象计数的方式。

## 与宿主资源区分

树调用额度不等于实例 CPU/内存额度。创建账户不自动获得新插件实例；需要隔离实例时另行申请本机插件池资源。创建更多子账户不能复制一份内核预留或父级预算。

配额与授权错误区分：对象数/配置冲突为 409 QUOTA_CONFLICT；瞬时调用限流为 429 RATE_LIMITED，提供 Retry-After；本机实例资源不足为 503 RESOURCE_EXHAUSTED 或异步 waiting_resources。

## 异步批次

批次提交/轮询受HTTP限流；每项首次实际执行按一个根业务调用扣每日额度，尚未执行不占调用并发。子调用共享该项根预留；安全重试不重复扣次数，UTC日切换也不能重复结算旧项。树级排队数量与输入/结果存储初始硬上限见[批次执行](../tasks/batches.md)，不通过子账户或多个Key复制预算。

## 扩展链额度

扩展不复制宿主、账户树或API Key预算。data贡献加载和执行计入实际根服务或微部署原限额；skill handler在自己的服务按原资源及并发准入。整个链继承同一根调用预留、剩余deadline和取消范围，扩展层和安全重试不能重置每日次数或创造另一份调用并发。

扩展版本/部署/贡献存储属于可计量核心对象，限额由对应管理策略执行；完整链最多16层、贡献数据≤256KiB，拒绝以无限链、重复handler或多层缓存规避对象数和内存上限。
