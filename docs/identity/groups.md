# 权限组版本与绑定

[文档总目录](../README.md)

> 规格版本：2.6.0；状态：待实现的规范性设计。MUST/必须表示实现及验收要求，不能理解为现有功能。

## 规则结构

PermissionGroup 保存身份和 owner；GroupVersion 保存不可变 rules。每条规则是 action + ResourceSelector + 可选 RuleConditions。首版无嵌套组、无角色循环继承、无任意表达式脚本。

ResourceSelector.kind 确定对象类型；match=ids 限定具体 ID，owned_by 固定到明确账户，all 仅扩展到该类型内。未知动作或动作不接受该资源类型时拒绝发布。

同级有效来源取并集；父级、源凭证、固定上限、客户端和插件代理条件取交集。移除某组只移除该来源；其他独立合法来源仍可授权。

来源追踪需要保留每条规则的替代授权路径：同级来源是 OR，祖先/源凭证约束是 AND。不能因为某个历史来源被撤销，就把另一个当前独立来源授予的同一权限一并抹去。直接绑定某组的授权随该绑定撤销；仅将组版本作为快照选择模板时，仍以记录的实际授权来源和固定上限判断，不把模板本身当永久权力来源。

## 创建、版本发布与归档

1. createGroup 创建 v1，private 默认仅本人及有权限的管理者可见。
2. 发布 public 必须有公共组发布权限；private 用户不能借改 visibility 扩权。
3. publishGroupVersion 读取组 ETag，新版本 rules 全量提交，版本号由服务端加一。
4. Grant 固定 group_id/version；派生快照同时保存展开规则及来源记录。
5. 新版本发布不会替换旧绑定；显式换绑需要重新检查实际创建者可授予范围。
6. archiveGroup 撤销该组作为有效来源的绑定，保留版本及审计供历史核查。

归档或解绑使后代求交结果收窄；不能只保存一份不可撤销的展开 allow 列表而丢弃其来源。快照授权上限和当前有效来源同时参与判断。

## 非法情况

新增规则超出创建者权限、资源越界、向自身增加更高角色、对子账户另绑全局组企图超过父级、篡改组版本均返回 403/409，并审计。发布组不代表创建者自动持有组内权限。
