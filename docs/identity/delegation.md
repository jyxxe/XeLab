# RPC 委托句柄与可信主体上下文

[身份权限目录](README.md) · [RPC 公共协议](../communication/grpc.md)

## 两层记录

ExecutionDelegation 保存任务/调用固定授权上限和当前主体/源凭证关系。RpcDelegation 是一次具体转发交给目标实例的不透明调用句柄，绑定前者及当前实例、调用或执行尝试。

句柄由至少256bit随机值构成，服务端保存 HMAC 校验摘要，不嵌入可被插件改写的角色。目标插件不需要离线公钥接口：它验证 mTLS 对端确为内核，再接收内核已经校验的 RpcContext.subject_id/actor_instance_id。不能接受任意容器提供的同名正文作为主体证明。

## 内核签发与验证

1. 原请求经用户/服务凭证授权，形成固定上限和当前有效来源。
2. 解析并准入目标实例，生成 RpcDelegation，绑定 instance_id/generation、call_id 或 execution_id、执行委托及到期。
3. 内核经 mTLS 向目标发送句柄及可信主体；插件只在该来源接受业务请求。
4. 插件调用 HostService 时提供句柄；内核按实际证书实例验证目标绑定，并重新检查账户、源凭证、固定上限、插件审批及资源。
5. RpcContext 中自报 subject/actor 若非空却与推导结果不符，拒绝请求；不得拿它替换已验证身份。

普通调用句柄到期不晚于调用整体 deadline，任务执行句柄不晚于该步骤/任务的较早期限，并始终受源授权有效期约束。账户、源凭证或实例失效会提前终止使用，不依赖句柄自然过期。

## 下游与终止

插件 A 请求 B 时内核建立新的下游 Call 和 B 的句柄，保存父 RpcDelegation；不把 A 的目标实例句柄原样交给 B。所有祖先收窄条件和取消状态继续生效。

普通业务 Call 终止、任务尝试租约/fence 失效后，不允许原插件使用旧句柄继续发起业务子调用。结果核实 Query 由内核在当前读取授权下单独代理，不构成重开业务调用授权。

所有句柄仅在内存和受保护通道出现；日志记录其非敏感 ID。持久化原始句柄或把它替换成无来源关系的普通用户会话均被禁止。
