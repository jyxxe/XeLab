# Extension Plugin：扩展插件

[文档总目录](../README.md) · [架构](../architecture/extension-plugins.md) · [插件开发](../plugins/README.md)

> 规格版本：2.8.0；状态：待实现的规范性设计。本文不表示已存在扩展加载器、运行服务或可安装制品。

Extension Plugin 是依附宿主、为宿主扩展功能的第一类插件。宿主可以是普通插件、微插件或另一个扩展插件；扩展链最后必须落到一个实际的普通OCI宿主，或由MPR承载的微宿主。扩展本身不创建OCI实例、独立端口或工作负载证书。

“任意种类”表示三种宿主类型都可被明确绑定。具体宿主版本必须主动声明兼容的扩展点，并由其受审适配器处理扩展；没有扩展点的旧插件不会因安装扩展而自动获得加载能力。

| 插件类型 | 交付与执行 | 核心关系 |
|---|---|---|
| 普通插件 | 签名OCI制品及独立容器 | 安装、部署、实例及节点资源预留 |
| 微插件 | 不可变微源码，由MPR中的受限worker执行 | 独立微对象，固定MPR安装/部署及微资源组 |
| 扩展插件 | 独立清单及严格JSON贡献，由宿主扩展点解释或转发固定处理器 | 独立扩展对象，固定宿主、扩展点、版本及完整宿主链 |

## 两种贡献模式

`data`模式提供有界JSON贡献。宿主扩展点的已声明适配器按其语法解释贡献及业务输入，输出必须符合该点的结果Schema；它可以扩展字段映射、规则、格式描述、模板或其他宿主已经实现的声明式能力。JSON中的字符串不是可执行JS、shell或宿主路径。

`skill`模式固定一个已经注册的处理器Skill UUID及definition_digest。宿主监督器通过核心HostService.InvokeSkill调用该处理器，核心重新检查完整扩展链、处理器授权与契约兼容性。业务输入不能替换Skill、宿主或扩展制品。

两种模式均可形成自己的公共候选Skill；data候选执行宿主点的数据适配器，skill候选执行固定处理器。创建部署只生成候选，是否注册、启用及调用权限分别管理。扩展不原地改写宿主已经发布的Skill定义。

## 典型关系

普通文档解析插件可声明格式映射扩展点，扩展提交符合该点Schema的格式数据或绑定固定解析Skill。微插件可声明只读JSON规则扩展点，MPR1.3把固定贡献投影给明确支持扩展的微版本。扩展还可声明自己的扩展点，让下一层扩展补充规则；整个链始终保留来源、契约和权限边界。

每个扩展部署恰有一个宿主，所有宿主边及固定处理器强依赖共同构成无环图。最多16层，拒绝自依赖、间接循环及执行重入。宿主声明扩展点不构成它对所有已安装扩展的反向强依赖。

资源沿宿主链计入实际执行根，不按层复制节点或微部署预算。MPR父容器仍默认4vCPU/4GiB，微根仍默认250mCPU/256MiB，联网默认关闭；扩展不能通过处理器或链式依赖放宽这些设置。独立处理器另按其原部署预算准入。

本版不加载任意JS模块、原生动态库或宿主程序。若以后增加代码型扩展，需要新的宿主ABI、运行时能力声明、制品验证及执行隔离契约，不能把它作为现有data/skill模式的配置开关。
