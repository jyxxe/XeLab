# 扩展生命周期与恢复

[扩展目录](README.md) · [执行协议](execution.md) · [验收](acceptance.md)

> 规格版本：2.8.0；状态：待实现的控制契约。管理HTTP操作见[扩展逐接口目录](../api/operations/extension-plugins/README.md)。

## 发布与创建部署

1. 创建ExtensionPlugin身份，核心固定真实owner及默认私有范围。
2. 上传contribution.json，发布版本时检查严格JSON、清单、点契约、处理器引用和实际包/源码摘要；此时不生成未绑定宿主的候选Skill。
3. 创建ExtensionDeployment，核对唯一typed host、宿主点和双方授权，解析完整依赖图并拒绝环/超过16层；固定版本、宿主、config和limits。
4. 核心生成固定candidate_skill，初始enabled=false、phase=disabled；候选不自动注册，也不自动启用。
5. 有权用户分别注册候选、启用扩展部署与Skill。只有当前宿主链、实际root实例和准备状态均满足时才可调用。

版本发布后内容不可变；宿主、版本、配置或limits变化需要新扩展部署及候选Skill。旧部署不提供任意PATCH config/host的热替换入口，不能为了修复一个故障将旧任务重绑到新链。

## 期望状态与观测状态

| 转换 | 前置条件及收敛 |
|---|---|
| disabled → preparing | enabled=true，扩展来源/权限有效，固定宿主及扩展点兼容且已就绪 |
| preparing → ready | 实际root的Prepare成功，逻辑closure与完整运行快照一致 |
| 可运行态 → waiting_host | 固定宿主、祖先扩展、微运行时或root实例不可用；先撤销对应路由并作废准备句柄 |
| waiting_host → preparing | 同一固定逻辑宿主链恢复，当前权限仍有效；重新准备原版本/贡献 |
| preparing → failed | 贡献/Schema/摘要/处理器/宿主协议不匹配；保留明确原因，不寻找同名替代 |
| 可运行态 → draining | 停用或归档，先撤新路由，传播取消，再逆序Release及清理 |
| draining → disabled | 普通停用且所有相关执行/准备/租约已排空 |
| draining → archived | 归档意图且执行/准备/租约已排空；历史版本与Call证据保留 |

enabled是期望状态，phase是控制器观测；写入停用不等于已排空。清理失败保持明确的draining/failed和待清理记录，不能重新开放路由或提前删除来源证据。

## 宿主先启动，扩展后启动

按宿主与处理器强依赖图拓扑顺序准备，祖先先Ready，子扩展随后准备。停止时逆序撤销子路由及排空，再释放上层准备状态，避免子扩展继续调用已停止宿主。

宿主提供扩展点不建立对所有扩展的反向启动依赖。一个扩展准备失败只使受影响点或候选不可用；核心管理、宿主其他独立能力和无关扩展不必等待它。

宿主停用、归档或权限撤销会使下游扩展停止新调用并收敛；不能因扩展仍enabled就重新启用宿主。恢复只使用原固定绑定，不改用另一个同名部署、另一MPR安装或最新处理器。

## 两种摘要与句柄失效

host_chain_digest固定逻辑绑定、版本/包、点契约、config/limits及处理器引用。健康、enabled、实例代次与微资源设置不进入稳定逻辑摘要；这些值另在runtime_snapshot中核对。

宿主重启或代次变化时，旧准备句柄立即失效。核心对同一逻辑closure读取新运行快照并重新Prepare；旧代响应不得覆盖新观察。准备句柄可缓存和重建，但不表示长期授权，也不持久化用户执行内存。

微宿主停用后手动调整resources/network_enabled会推进其generation，关联扩展必须重新准备并遵守当前设置；它不授权扩展绕过新的网络关闭或资源上限，也不要求把原微包或扩展包重算为新代码。

## Call、batch与故障

每个Call保存固定扩展链、处理器定义和运行快照，结果关联真实扩展来源。batch及工作流固定原扩展Skill和链；暂停或恢复不选择当前最新扩展，不把新配置套到已发送的旧业务请求。

纯计算安全恢复仍受原定义、输入、业务键和deadline约束；非重复安全处理器在超时、断线或OOM后必须先查询证据。未知副作用保持unknown，不因宿主或扩展重启就重放。

data适配器或handler失败不得返回部分JSON成功。实际根为微部署时，组OOM可能影响同组多个Call；扩展本身不构成新的独立故障域。已经发出的外部请求不因Release、取消或归档被宣称撤回。

清理扩展部署不删除宿主、handler、共享Blob或其他扩展。删除与卸载不级联越权；历史来源、审计、幂等记录及未知结果核实材料按平台保留规则独立保存。
