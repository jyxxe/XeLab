# 控制循环、事务与崩溃收敛

[文档总目录](../README.md)

> 规格版本：2.8.0；状态：待实现的规范性设计。MUST/必须表示实现及验收要求，不能理解为现有功能。

## 创建/变更事务

1. 验证当前完整授权链和 If-Match，锁定目标部署、节点预算及相关卷。
2. 按固定顺序锁账户祖先：根至叶；锁资源时按 UUID 排序，避免死锁。
3. 记录幂等键、期望配置 revision、Operation、资源预留及 outbox；同一数据库事务提交。
4. 控制器读取 outbox，按稳定 instance_id 创建/检查 OCI 容器。运行时对象标签必须含 instance_id、deployment_id、generation。
5. 初始化与探针完成后，再在事务中登记当前能力就绪状态及 observed_generation；发布路由快照。

控制器只在单内核进程中持有活动领导锁。使用 PostgreSQL advisory lock，进程失去数据库连接即停止调度和提交；不宣称其解决多节点选主。

## 中断点处理

| 中断点 | 重启后的动作 |
|---|---|
| DB 已提交，容器未创建 | 用同一实例 ID 继续 ensure，不新增第二份预留 |
| 容器已创建，观测未保存 | 由标签找回，验证镜像/代次/配额后接管或停止 |
| 路由缓存已过期 | 从授权有效且探针仍 Ready 的记录重建，缺失则不路由 |
| 禁用已提交，容器仍在 | 不恢复路由，继续排空和 stop |
| OCI 对象无数据库实例 | 隔离标记为 orphan，确认不属于有效实例后停止；保留审计 |
| DB 声称实例运行但实际丢失 | 标记失败，按重启预算重新启动，不复用外部运行事实 |

## 周期与幂等

启动执行完整对账；运行中每 5s 增量对账，事件到达可提前唤醒。重复执行 reconcile 必须得到同一稳定期望，不产生重复卷或重复任务。

资源释放以实际容器停止、卷卸载完成为依据；镜像或备份占用通过独立存储账本管理。管理 API 提交操作后不等待完整控制循环，客户端轮询 Operation。

## 扩展链对账

扩展控制器以固定宿主链、版本、配置摘要及根运行代次对账：先核实宿主基础Ready，再按拓扑幂等Prepare；停用、归档或根失效时按逆拓扑撤新路由并Release。扩展没有可由标签找回的独立OCI实例，不能为同一逻辑扩展重复申请节点容器预留。

根重启使旧扩展句柄失效；只在原精确宿主链恢复、独立来源与当前权限有效后重新Prepare。扩展记录或根自报成功均不足以证明外部handler副作用未发生，Call恢复仍按固定Skill、幂等与unknown证据处理。详见[扩展控制](extension-plugins.md)。
